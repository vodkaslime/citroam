## 当前产品方案摘要（2026-09-03）

本轮“最简单、流畅的 Agent”设计已经正式纳入产品基线。Agent 不是一个需要持续陪伴用户的聊天机器人，而是捕获栏旁按需出现的一张临时对话纸片：用户主动打开，说清一件眼前的事，看见真实结果，然后继续使用画布或总览。

- 普通捕获、拖动、编辑、搜索、总览、完成、撤销与本地备份始终走本地链路，不因 Agent 不可用而降级。
- Agent 只把自然语言转换成既有 Card / Workspace action；不生成坐标、不重排画布、不引入项目层级、自动排程、提醒、推荐或评价。
- 唯一目标的动作直接执行并提供“查看 / 撤销”；批量动作先预览确认，删除与覆盖沿用安全确认。
- 歧义、失败、超时、断网或请求期间现场变化时保持 no-op，并明确告知用户“画布没有变化”。
- 对话默认关闭，只在用户主动打开后加载能力；关闭后不留下常驻聊天界面，短会话记录也不写入 Workspace 或备份。

完整的行为契约、验收编号、状态机、动效、焦点与隐私边界分别见[产品需求：可选对话 Agent](./product-requirements.md#可选对话-agent)和[产品设计：可选对话 Agent](./product-design.md#可选对话-agent)。

## 本轮产品设计落档：人本、最短的对话 Agent（2026-09-03）

本轮把“像最舒服的对话一样管理与完成日常任务”落成一个克制的、按需出现的操作层，而不是把 citroam 变成聊天产品。产品契约固定为：

```text
主动打开 → 说清一件事 → 看见真实结果 → 继续生活
```

这条链路只替用户省下一次明确的点击，不替用户思考、规划或安排生活。对话是临时工具，不是第三个视图、常驻角色或新的任务系统：

- 首版默认使用本地确定性解释器（`localAgentModel`），不需要账号、网络或外部模型就能工作。
- `AgentModel` 保留为可替换边界；未来若接入外部模型，必须由用户明确启用，并在发送前说明数据去向，默认仍不上传内容。
- 用户主动打开对话，说清一件事，看到画布或总览中的真实结果，然后继续生活；没有请求时不问候、不推荐、不规划、不提醒、不评价。
- 普通捕获、拖动、编辑、搜索、总览、完成、撤销和本地备份永远走本地链路，不因 Agent 不可用而降级。
- Agent 只把语言转换成现有 Workspace action：支持创建、查找 / 打开、改标题或备注、改日期 / 时段、移到随手页、完成 / 恢复，以及用户明确指定集合的批量动作；不新增项目、计划、提醒或自动排程模型。
- 单张可撤销动作直接执行，批量动作一次预览确认，删除或覆盖继续使用安全确认；歧义、无效、超时、断网或现场变化时保持 no-op，并明确告诉用户画布没有变化。
- “画布 / 总览”始终是唯一的主要操作现场；用户主动切换时关闭临时对话且保留新视图按钮焦点，Agent 为展示结果进行的内部导航不关闭回执。

本轮补充的体验判断是：Agent 只代替一次点击，不代替用户思考。用户说清一个眼前的意图，看到一个真实、可撤销的结果，然后继续生活；不确定时只问一个最小问题，不用连续对话、建议或人格表演制造新的使用链路。对话草稿与普通捕获草稿隔离，关闭后画布恢复安静；会话记录只存在当前应用会话，最多保留最近 8 条消息，不进入 Workspace、备份或永久上下文。进入随手页时，已有内容若已在当前视野内则保持现场，只有超出视野才 fit，避免无意义跳动。具体行为边界见[产品需求](./product-requirements.md#可选对话-agent)与[产品设计：可选对话 Agent](./product-design.md#可选对话-agent)。

本轮补充 Agent 已完成结果定位回归后，最新自动化总数为 377 项；文档后部出现的 360 项、369 项、370 项、371 项、372 项、374 项与 376 项均作为此前历史基线记录保留。

本轮新增的窄窗口可见性契约：首次加载 Workspace 时，如果真实舞台已测得 `760 × 560` 一类最小桌面尺寸、当前仍使用默认视口且正在打开初始日期页，系统只在内存中按舞台尺寸 fit 日期场景（包含当前页开放 Card），让页面第一眼完整可见；不写 Workspace、不生成 Undo，也不影响后续翻页或用户手动视口。尺寸尚未测得或用户已有自定义视口时保持原现场。日期页的时间围栏标签在缩放时使用反向缩放，保持图标与文字接近正常屏幕可读度，不改变围栏命中几何。

这组约束是“简单、流畅、服务于人”的实现边界，后续实现和评审都以它为准。

## 本轮设计与 Agent 接入落地（2026-09-02）

在保持本地优先和“写下一句话 → 放在这一页 → 随手维护 → 完成”的前提下，citroam 增加一个默认关闭、由用户主动触发的对话操作层。它不是常驻聊天窗口，也不是新的任务系统，而是一张从捕获栏上方短暂展开的对话纸片：

```text
打开对话 → 说一句 → 看见结果 → 继续生活
```

- 普通捕获、编辑、拖动、搜索、总览、完成、撤销和备份继续走本地确定性链路，不经过模型。
- Agent 只把明确请求翻译成既有 Card / Workspace action；模型不能直接写数据、生成坐标或改变画布结构。
- 单张可撤销动作直接执行；批量动作先预览并一次确认；删除与覆盖等破坏性操作沿用安全确认。
- 对话草稿与普通捕获草稿隔离，关闭、失败、超时或断网都不丢输入，Workspace 保持原样。
- Agent 不主动问候、推荐、规划、提醒、复盘或评价；温度来自安静、自然、克制和可靠的结果反馈。
- Agent 只减少一次明确维护的点击成本，不承担开放式问答、生活规划或新的任务管理流程；它不可用时，产品仍然完整可用。
- 从已经平移很远的随手页首次进入日期页时，不继承随手页视口；先使用安全的日期场景视口，让新页面立即可见。已访问过的日期页继续恢复自己的会话视口。
- 触控手势保持单一归属：第一根手指落在 Card 上时先进入 Card 拖动；第二根手指随后落在 Card 或空白画布，都升级为同一场双指缩放，Card 不移动且只提交一次 viewport。

这次交付把“舒服的对话”定义成一次很小、很明确、随时可以退出的维护动作，而不是一个需要陪伴用户的聊天人格。产品只提炼安静、自然、克制和对日常动作的体贴感，不复制任何具体创作者的角色、台词或视觉资产。对话入口、普通捕获和画布维护仍然各自独立；用户不需要为了使用 Agent 改变自己的工作方式。

Agent 的产品契约固定为：

```text
主动打开 → 说清一件事 → 看见结果 → 继续生活
```

- 能由本地确定性操作完成的事情，不调用 Agent。
- Agent 只处理捕获、查找、改名、备注、日期 / 时段、移到随手页、完成、恢复和明确指定的批量动作。
- 单张明确动作直接执行；批量动作先给一次预览；删除或覆盖必须经过现有安全确认。
- 不确定、无效、超时、断网或现场已变化时，整个动作保持 no-op，并明确告诉用户画布没有变化。
- 一次操作结束后不主动追问、不推荐下一步、不评价用户，也不留下常驻聊天痕迹。

详细的界面、状态机、动效、隐私边界与验收规则见[产品设计：可选对话 Agent](./product-design.md#可选对话-agent)和[产品需求：可选对话 Agent](./product-requirements.md#可选对话-agent)。该能力当前仍属于发布门槛，不能在真实窗口验收完成前描述为正式可用。

## 一页共识

citroam 是一块本地优先、按天翻页的生活与工作待办画布，不是一套任务管理方法。

> 想到就放下，需要时找得到，做完便过去。

```text
写下一句话 → 放在这一页 → 随手维护 → 完成
```

- Card 同时容纳想法与临时待办；创建只需要一句话。
- 日期天然是一页，不创建日期对象，也不在页内嵌套日期卡片。
- 日期页只有“随时、上午、下午、晚上”四个柔性时段；随手页容纳尚未决定日期的内容。
- Card 可以自由摆放、拖入时段吸附，也可以合法停在时段或日期画布的视觉边界之外。
- “画布 / 总览”共享同一批 Card；画布负责维护空间现场，总览、搜索和“看全本页”负责看全与找回。
- 日期文字按上下文减法：同年省略年份，跨年时明确显示年份；相对日期与星期各只出现一次。
- 用户手动翻页或切换一级视图时，先提交合法草稿，再结束不属于新现场的详情与编辑态；重复进入当前页保持现场不变。
- 空白页保持安静，捕获栏就是唯一的下一步提示。
- 系统不自动排序、续期、搬运、提醒、评价或解释普通空间位置。
- 可选 Agent 只在用户主动打开对话时处理明确请求，不引入项目层级、Now、情境匹配或复杂任务状态。
- Agent 默认关闭；启动、普通捕获、翻页和画布维护都不初始化模型、不发起网络请求。
- Agent 与拖动、平移等本地操作并发时，所有提交都以最新 Workspace 为准；不能用旧手势或旧响应覆盖用户刚完成的修改，无法安全合并时整体 no-op。普通捕获、手势、Agent 与卸载前的防抖视口写入共用串行保存队列，较新的本地状态不能绕过队列写入。
- 时间、优先级和备注都是可选信息，不能阻挡创建。

## 人本产品原则

citroam 不试图成为用户的教练、裁判或管理者。即使接入 Agent，它也只做好四件事：

1. **接住**：一句话就能留下想法或临时任务。
2. **摆放**：用户按自己的直觉决定日期、时段和位置。
3. **找回**：画布、总览和搜索保证内容不会因自由摆放而丢失。
4. **完成**：完成后安静离场，不评分，不庆功，也不制造新的心理债务。

技术应退到体验背后：核心闭环本地、离线、无需账号即可完整使用；用户内容可以导出，持久修改有撤销或备份恢复路径。任何新能力都不能要求用户理解新的系统概念，不能擅自替用户思考、安排或解释生活。

## 可选的对话操作层

Agent 不是第三个一级视图，也不是会主动说话的产品人格。它是捕获栏旁一个按需展开的对话入口：

```text
说一句 → 看见画布变化 → 继续生活
```

- 普通输入加 Enter 仍然直接创建 Card，不经过模型。
- 用户主动打开“对话”或使用 `⌘ J / Ctrl J` 后，才把自然语言解释为 Card 操作。
- 对话入口只在用户主动打开后才加载所需能力；关闭对话即停止本次操作，不在后台保持会话。
- 明确的单张可撤销操作可以直接执行；批量操作先预览，删除等破坏性操作必须确认。
- Agent 只产生结构化操作意图，本地规则负责解析目标、校验后果、修改 Workspace 与生成 Undo。
- Agent 的时间意图也必须经过本地校验：具体时刻要与声明的时段一致，结束时间必须有开始时间且晚于开始时间；不合法的意图保持 no-op。
- 新建、移动、完成和定位继续复用画布既有行为，不建设第二套 Agent 数据模型。
- 只向模型提供完成当前请求所需的最小上下文；对话不可用时，离线核心功能保持完整。
- Agent 不主动推荐、催促、评分、规划生活或重新排列画布。

### 2026-09-02 设计落地：最短、最舒服的 Agent 链路

Agent 的产品承诺不是“拥有一个会聊天的助手”，而是让用户在不想打开详情、逐张操作时，用一句自然的话完成一次明确维护。它遵守以下最短路径：

```text
打开对话 → 说一句 → 看见结果 → 继续生活
```

- 对话从捕获栏上方临时展开，关闭后画布恢复安静，不增加第三个一级视图、侧栏或永久聊天记录。
- 普通捕获永远直接创建 Card；对话有独立草稿，打开和关闭都不吞掉正在输入的标题或快速 token。
- 唯一目标的单张动作直接执行并给出“查看 / 撤销”；批量动作只增加一次预览确认，删除或覆盖本地内容继续使用默认取消的安全确认。
- Agent 只翻译成既有 Workspace action，不生成坐标、不直接写数据、不建立第二套任务模型；失败、超时或无效意图统一保持画布原样。
- 对话只在用户主动打开并发送请求后出现，不问候、不推荐、不规划、不复盘、不催促，也不评价用户。
- 只向模型提供完成当前请求所需的最小上下文；对话历史默认只存在于当前会话内，最多保留最近 8 条消息并自动滚到最新回执，普通功能离线完整可用。

这一设计把“舒服”定义为低打扰、少确认、结果可见、随时可撤销，而不是拟人化、热闹或更复杂的自动化。

当前工程已经接入这层对话能力的首条完整行为链路：入口与独立草稿、结构化意图、本地 policy、目标消歧、单张直达、批量临时轮廓预览、批量确认、破坏性确认、可见回执、原子 Undo、短窗口对话记录与自动滚动、以及失败 no-op 均已有工程实现。并发手势与异步响应的最新 Workspace 合并、完整视觉、焦点边界、外部模型启用说明、全量回归与真实 Tauri 窗口仍属于发布门槛；全部通过前不对外描述为正式可用。

## 四个核心概念

| 词 | 含义 |
| --- | --- |
| Canvas | 当前打开的自由工作空间。 |
| Card | 一句话、一个念头或一项待办。 |
| 日期页 / 随手页 | 天然存在的页面，不需要创建或管理。 |
| Area | 随手页中按需画出并命名的视觉范围，不是 Card 容器。 |

用户只需要决定“放在今天，还是先放在随手页”，不需要先学习任务管理术语。

## 两种视图，同一份内容

| 视图 | 作用 | 不做什么 |
| --- | --- | --- |
| 画布 | 捕获、自由摆放、维护空间现场。 | 不自动排序、分组或解释普通位置。 |
| 总览 | 以稳定列表展示未完成与已完成 Card，并定位回画布。 | 不保存第二份顺序，不建设收件箱、Today、统计或批量排程。 |

总览不是新的主链路。它只提供一个确定答案：每张未删除的 Card 都可以被看见和找回。

## 当前工程基线

当前工程已经具备：

- 日期翻页、今天直达、任意日期选择与随手页。
- 四个柔性时段、自由拖动、时段预览与释放吸附。
- 总览、搜索、定位、“看全本页”、完成、恢复与撤销。
- “画布 / 总览”只挂载当前正在使用的一级视图；切换时结束旧现场，不在后台保留一棵不可见但仍参与渲染和焦点顺序的完整界面树。
- 总览先呈现 64 行，再在用户接近末尾时自动续载下一批；“再显示 N 张”同时保留为可见、可聚焦的手动入口。未完成总览的日期页与随手页按实际数量比例进入首批，顶部数量始终显示完整数据，而不是当前已渲染行数。
- 总览在 Workspace 尚未加载或读取失败时保持真实状态：显示“正在打开本地内容”或可重试的错误，不把暂时为空误报为“没有未完成的卡片”；只有加载成功后才渲染空状态。
- 空随手页没有 Card 或 Area 时，“看全本页”明确禁用；底层仍是安静的 no-op，不跳视口、不保存，也不制造撤销记录。
- Inspector、Card 就地标题编辑、快速语法与中文输入法保护。
- 搜索输入会同步暴露当前键盘高亮结果，视觉焦点与辅助技术感知保持一致。
- 日期导航会在今天 / 明天 / 昨天显示相对称呼，在普通日期显示星期，但不会在同一个标题里重复星期。
- 应用在前台跨过午夜，或用户重新回到应用时，会刷新相对日期和“今天”入口；当前页面与 Card 保持原位，不自动翻页、不保存。
- 捕获栏在今天 / 明天 / 昨天使用相对称呼，翻到更远日期时直接写出月日或年份，不再用“放进周六”模糊目标。
- 本地持久化、保存失败重试、旧数据迁移与本地备份。
- 页面视口记忆、单一手势会话、临时层焦点与撤销作用域保护。

## 取舍规则

新增能力必须同时通过以下判断：

1. 不让“写下一句话”多一个必经步骤。
2. 不要求用户先学习任务管理方法。
3. 不替用户安排生活，也不把普通空间位置解释成硬信息。
4. 不整理时依然可以记录、找到、修改和完成。
5. 派生视图不能制造新的必填字段、持久顺序或维护成本。
6. 对核心链路没有明显帮助时，默认不加入。
7. 核心闭环不能依赖账号、网络或外部服务。
8. 不能用通知、评分、连胜、恐惧或亏欠感制造回访。
9. 能由明确、确定的本地逻辑完成时，不调用 Agent；只有用户主动发起的对话请求可以使用模型推断。
10. Agent 的结果必须可见、可预览或可撤销，不能直接绕过本地规则修改 Workspace。
