本文描述 citroam 应该达到的体验。已经确定的产品模型与仍待验收的质量项，统一以[产品需求](./product-requirements.md)中的状态说明为准，不因文档中出现某项交互就默认它已经交付。

Agent 设计以 2026-09-04 的“画布原生 Harness”决策和下方“画布原生 Agent”章节为当前基线；此前关于临时对话纸片、独立对话页面和本地正则替身的文字只记录设计如何收敛，已不再代表当前方案。若历史描述与当前验收项有差异，以最新基线、既有 Card / Workspace action 和本地 reducer 约束为准。

本轮设计决策（2026-09-04）：Agent 是画布上的原生操作层，不是与画布、总览并列的第三个页面。它以轻量面板覆盖在当前画布上，画布、时间围栏和 Card 始终可见；用户可以随时收起面板或切换总览，并保留当前会话中的对话草稿、结果和待确认状态。温度来自安静、自然、克制和可靠的结果反馈，不来自人格表演；它只把用户明确说出的一句话翻译为既有 Card 动作，并保留可见结果、最小确认和随时撤销。

**原生支持声明**：Agent 是 citroam 的基础能力，随画布一起存在，不需要用户先开启，也不提供独立的 Agent 页面。用户打开画布内“对话”即可提交请求；生产实现通过 Tauri 管理的 DeepSeek Harness sidecar 运行真实模型，模型与网络只在用户提交请求时启动，不能把普通画布操作与网络绑定。

**默认状态**：Agent 入口在画布工具层始终可达，而不是“默认关闭后等待启用”。应用启动、打开画布、翻页和普通捕获不启动 Harness、不初始化模型、不发起网络请求；“可用”只表示用户随时可以打开面板发起请求，不表示 Agent 会自动打开、自动发言、读取内容后自行整理，或在后台执行任何动作。没有用户明确请求时，Agent 保持安静，画布、总览和普通捕获继续按本地路径工作。

### 一等公民判定标准

“一等公民”不是把 Agent 做成更大的聊天界面，而是让它在产品结构上与画布、总览拥有同等的可达性、可靠性和数据权限边界：

- **同级入口**：画布工具层固定提供“对话”入口；对话拥有自己的标题、输入、消息、候选、确认与回执，覆盖当前画布但不创建第三个一级页面。
- **同源数据**：Agent 只能调用现有 Card、Placement、Workspace action、视口和 Undo；它不建立平行任务表、聊天档案或专属坐标模型。
- **同等可靠**：普通点击、拖动、搜索、总览与对话都以最新 Workspace 为唯一事实来源，共用串行保存、焦点、撤销和失败 no-op 协议；Agent 不能覆盖用户刚完成的本地操作。
- **同等可用**：DeepSeek Harness 作为生产运行时按需启动；未构建 Harness、缺少密钥、断网或 provider 失败时，该次对话请求明确失败且 Workspace 不变，画布、总览和普通捕获不受影响。
- **不替用户做主**：Agent 只有在用户发送明确请求后才行动，不主动问候、规划、提醒、推荐、整理或评价；视图切换只改变工作空间，不改变用户对内容的最终解释权。
- **可切换、可恢复**：对话草稿、最近 8 条消息、候选、待确认与执行中状态在当前应用会话内跨面板收起保留；每次真实修改都回到 Workspace，并提供既有的查看、撤销或安全确认路径。

后续任何 Agent 功能都必须同时满足以上六条；如果需要新增开关、隐藏入口、第二套数据模型或独立生命周期，则不属于 citroam 的原生 Agent 设计。

历史设计记录（2026-09-02，已被本轮原生工作空间方案取代）：对话曾被设想为不想打开详情、逐张点击时的一条临时操作入口。该记录只用于说明设计演进，不再定义入口形态、视图层级或会话生命周期。产品气质仍然温柔、自然、有人味，但不模仿任何具体创作者的角色、台词或视觉资产；简单、沉默和可切换优先于拟人化与连续对话。

本轮实现边界（2026-09-04）：生产 Agent 通过 Tauri 管理的 DeepSeek Harness sidecar 运行真实模型。Harness 使用 SDK JSON-RPC profile，按需启动稳定 session，并只暴露 citroam 专用 `citroam_apply` 工具。`localAgentModel` 仅作为 Vitest 测试替身，不是生产退化路径；Harness 未构建、密钥缺失、网络失败或返回无效意图时，该次请求失败且 Workspace 保持原样。普通捕获、画布维护、总览、搜索、完成、撤销和本地备份始终不依赖模型。

本轮产品决策补充（2026-09-03）：Agent 的价值边界是“代替一次点击，不代替用户思考”。它只帮助用户用最舒服的一句话维护眼前的日常事项：创建一张 Card、把一张 Card 放到某天或某个时段、改标题、备注或优先级、完成 / 恢复，或查找并打开已有 Card。每次对话只承载一个明确意图；能直接完成就直接完成，需要判断时只问一个最小问题，完成后立即给出结果，用户可回到画布或总览继续生活。它不把任务管理变成聊天，不要求用户学习命令，也不通过连续追问、建议或人格表演延长链路。

本轮落档（2026-09-04）：上述原则已经固化为“画布原生 Agent”章节及对应验收项。Agent 是覆盖在当前画布上的原生操作层，不增加第三个一级页面；用户打开面板、说一句话，Agent 就把明确意图转成既有 Workspace action，完成后仍可回到画布继续生活。Agent 不主动发言、不自动整理、不自动规划、不催促、不评价，也不因普通捕获而介入。生产请求经 Tauri sidecar 进入真实 DeepSeek Harness；模型只能通过 `citroam_apply` 提出 `AgentIntent`，由本地 policy、reducer、并发保护与 Undo 完成最终修改。失败、歧义、迟到响应或现场冲突都保持 no-op，并明确说明画布没有变化。对话草稿、短历史和待确认状态只保留在当前应用会话，不写入 Workspace、备份或 Harness 运行目录。

**设计落点**：citroam 不把 Agent 做成“更聪明的任务管理器”，而是做成一个很短的对话操作空间。用户仍然决定要记录什么、放在哪里、何时完成；Agent 只在用户明确输入后把一句话可靠地翻译成一次既有操作。结果必须可见、可撤销、可切换，且不改变产品原本“想到 → 写下 → 放着 → 做完”的节奏。

为了让这套设计在评审和实现时保持一致，本轮 Agent 交互收敛为以下六个判断：

| 判断 | 设计结论 |
| --- | --- |
| 什么时候出现 | 画布工具层始终提供“对话”入口；启动、翻页和普通捕获不启动 Harness、不初始化模型、不发起网络请求，只有用户提交请求时才调用真实 sidecar。 |
| 用户要做什么 | 用一句自然语言表达一件眼前的维护事项；普通输入仍直接创建 Card。 |
| 系统能做什么 | 创建、查找 / 打开、改标题、备注或优先级、改日期 / 时段、移到随手页、完成 / 恢复，以及明确指定集合的批量动作。 |
| 系统不能做什么 | 不主动聊天、规划、提醒、推荐、评价、拆项目、重排画布或解释用户的生活。 |
| 结果如何落地 | 只执行既有 Workspace action；单张直达，批量预览，破坏性操作确认，结果可见且可撤销。 |
| 发生问题怎么办 | 歧义、无效、断网、超时或现场变化时整体 no-op，短句说明“画布没有变化”，用户可修改原话后重试。 |

这条设计约束转化为六个界面承诺：

- 入口原生：对话是画布工具层的一等入口；面板覆盖当前画布，收起不改变页面或内容。
- 结果直接：单张明确动作直接完成；批量动作只增加一次预览确认；真实变化写回 Workspace，回执留在对话中，“查看”才按需定位到画布或总览。
- 失败诚实：歧义、无效、超时、断网或现场变化时不修改内容，并说明“画布没有变化”。
- 人在控制：普通捕获永远本地直达，Agent 不主动说话、不规划、不推荐、不评价，所有持久修改都沿用现有确认与撤销。
- 现场不被覆盖：Agent、Card / Area 手势和视口变化并发时，提交必须基于最新 Workspace；不能用旧闭包或迟到响应抹掉用户刚完成的修改。
- 操作现场单一：画布、总览与面板共享同一 Workspace；切换或收起时提交合法 draft，保留对话会话状态，不让旧的 Card / Area 编辑现场漂到新视图。

同日的画布可靠性决策：首次从随手页进入日期页时，日期页不继承随手页可能已经平移到很远位置的视口。系统按当前舞台尺寸先计算安全的日期场景视口，让新页面立即可见；只有已经访问过的日期页才恢复自己的会话视口。这是一次界面现场切换，不创建数据、不保存 Workspace，也不增加 Undo。

## 设计命题

> 不是把 Todo 列表搬到无限画布上，而是让用户把想法或临时任务直接放进今天，或者先丢进随手页，再用自己的方式维护生活与工作。

citroam 的链路必须短：

```text
想到 → 写下 → 放着 → 做完
```

产品不要求用户先分清类型、项目、优先级和顺序。日期也不是需要创建的容器，而是像书页一样天然存在。

Agent 不改变这条链路，只把“写下、放着、做完”中的一次明确动作换成一句话：用户进入对话，说清要处理的 Card，系统用同一份 Workspace 完成动作并给出可见回执。画布仍是生活的空间现场，总览仍是完整索引；对话与它们同级，却不制造新的任务层级、聊天档案或维护负担。

## 人本软件

citroam 更像一张随时可以摊开的桌面，而不是教练、裁判或管理者。Agent 是桌面上覆盖画布的一层原生操作面板；它只在用户明确说话后帮用户动一下 Card。

- 不预测用户想做什么，也不替用户解释为什么没做。
- 不把未完成事项包装成失败、欠债或需要被系统纠正的行为。
- 不依靠账号、云端、通知和奖励循环换取黏性。
- 只对用户明确做出的动作给予确定反馈；所有自动行为都必须服务于可见性、可靠性或可恢复性。
- 本地内容属于用户：核心操作离线可用，可以导出，并有撤销或备份恢复路径。
- Agent 不主动开口，不根据内容判断用户，也不把对话变成新的生活管理方法。
- Agent 入口在画布工具层始终可达；启动时不启动 Harness、不初始化模型、不发起网络请求，普通捕获也不经过 Agent。

本项目所说的“宫崎骏式”只提炼安静、自然、克制和对日常动作的体贴感；不模仿具体角色、台词、插画或其他受保护的视觉资产。Agent 的温度来自低打扰与可靠回应，而不是人格表演。

技术的价值体现在启动快、输入快、拖动跟手、保存可靠和错误可恢复，而不是让产品显得比用户更会安排生活。

### 本地优先的 Agent 边界

Agent 的“智能”只存在于把一句话稳定地翻译成既有操作这一小段距离。生产路径使用 Tauri 管理的 DeepSeek Harness sidecar；Harness 只暴露 `citroam_apply`，避免模型获得与日常任务无关的工具：

- 应用启动、普通输入、翻页、拖动、搜索、总览和完成等路径不等待 Agent，也不由 Agent 介入；只有用户发送请求时才按需启动 Harness。
- Harness 只接收请求所需的最小文字与压缩后的 Card 元数据，不接收坐标、Area、视口、备份或历史。
- 模型只能通过 `citroam_apply` 返回结构化 `AgentIntent`；本地 policy、reducer、并发保护与 Undo 决定是否落地。
- Harness 未构建、密钥缺失、断网、超时或返回无效意图时，保持 no-op 并说明“画布没有变化”；普通本地能力继续可用。

## 设计哲学

### 简单

- 一张 Card 只需要一句话。
- 今天天然存在，空白也合法。
- 一个动作只产生一个直接结果。
- 低频属性藏在详情，高频动作留在表面。

### 易用

- Enter 创建，拖动移动，点击修改，圆圈完成。
- 日期页、随手页与总览使用同一份 Card。
- 用户不理解任何任务管理方法，也能完整使用。
- 保存、失败、撤销和搜索是安全基础，不是新流程。

### 随性

- 可以认真摆放，也可以一直不整理。
- 今天可以充实，也可以完全空白。
- 昨天没做完不会被强制搬到今天。
- 完成不是评分，只是让 Card 从眼前轻轻离开。

### 自由

- 同一页中的位置由用户决定。
- 时段只表达柔性时间范围，不产生严格顺序。
- 系统不自动对齐、排序、归类、续期、提醒或评价。
- 自由必须有边界：任何 Card 都可以被“看全本页”、总览与搜索找回，定位后不能被其他 Card 完全遮住。

## 体验预算

简单不是少做视觉，而是严格限制产品向用户索取的注意力：

- 一次捕获只有一个必经动作：输入一句话并按 Enter。
- 新功能不得为捕获增加向导、确认、字段选择或等待外部服务的步骤。
- 一级常驻入口保持有限；除画布工具层的对话面板外，不新增额外常驻聊天框、推荐区、统计区、激励区或解释型空状态。
- 空白页继续保持安静，捕获栏是唯一的下一步提示。
- 昨日遗留继续使用“前一天还留着…”书签；系统不建设每日清零流程或自动搬运托盘。
- 只有用户明确发起移动时才改变 Card 的日期、时段或空间位置。
- 对话是画布上的原生操作面板；Harness 断网、失败或未构建时，本次请求 no-op，普通捕获、画布、总览与撤销仍保持可用。
- 每段动画必须表达按下、拿起、放下、吸附、完成、翻页或状态切换；加载之外没有常驻循环动画。
- 成功反馈短暂出现并沿用现有反馈轨道，不扩张为到处弹出的 toast 系统。
- 每增加一个可见概念，必须移除同等或更大的理解成本；否则默认不加入。

## 当前体验审计结论

最近一轮产品审阅的结论不是“再加一个功能”，而是把已经存在的自由还给用户，同时把几个容易误解的边界说清楚：

| 观察到的摩擦 | 当前设计决策 |
| --- | --- |
| 日期越过一天就需要手动创建新的容器 | 日期页改为像书页一样即时存在；前一天、后一天和日期选择只改变视图，不产生日期对象。 |
| 日期页看起来像一张可移动的大卡片 | 日期页不再渲染嵌套日期卡片；顶部导航是唯一日期标题，内部只保留柔性时段背景。 |
| Card 拖到上午/下午后位置不稳定，或拖出后无法继续 | 围栏只负责命中判断；拖动全程跟手，释放时才写入时段并吸附到可放置范围，围栏外仍是合法画布。 |
| 触控第一指从 Card 开始，第二指落到空白画布时被当成取消或重复拖动 | 第一指先保留 Card 拖动种子；第二指无论落在 Card 还是空白画布，都取消对象拖动并升级为同一场双指缩放。Card 坐标恢复原值，缩放围绕双指中点，最终只提交一次 viewport。 |
| 自由摆放后难以确认“所有内容在哪里” | “看全本页”、搜索定位和总览共同提供确定的找回路径；它们不替用户自动整理空间。 |
| 空随手页平移后点击“看全本页”，却跳到别页遗留的视口 | 空页没有可适配对象；控件明确禁用，底层保持眼前现场，既不保存，也不制造撤销。 |
| 已经看全后再次点击，顶部仍闪一次“正在保存” | 视口命令先比较可见现场；没有净变化就直接结束，不制造保存状态。 |
| 空白页用大段说明告诉用户下一步 | 日期页空白时不显示解释型占位文案，保留安静的画布与底部捕获栏；产品用操作本身说话。 |
| 时段、随手页和总览继续用小句解释自己的用途 | 只保留直接标签、真实状态与数量；轻松感由颜色、形状和动效表达，不靠反复拟人化。 |
| 日期页 Card 显示“今天 上午” | 页面已经表达日期，Card 只显示“上午”；总览与搜索再补全日期上下文。 |
| Card 没有时间、只有低优先级时，低优先级因为排在元数据第一项而变成橙色 | 强调色绑定时间语义，不绑定 DOM 顺序；优先级与备注保持中性色，不制造虚假的紧迫感。 |

| 打开 Card / Area Inspector 或就地编辑后，必须寻找关闭按钮才能回到画布 | 未形成平移的普通空白点击先提交合法草稿，再收起当前详情或编辑态，并把焦点还给原 Card / Area。 |
| Space + 左键或中键只是轻微抖动，画布也移动并产生保存 | 两种鼠标平移都使用 4 CSS px 意图阈值；阈值内不移动、不保存，越过阈值后即使回到原点也消费本次合成 click。 |
| 触屏轻点空白只开始又结束一次手势，Card / Area 详情仍留在屏幕上 | 未越过平移阈值的空白轻点与鼠标空白点击语义相同：提交草稿、收起详情并回到原对象；真正拖动时只平移。 |
| Card 就地编辑后点击空白，标题保存了但焦点掉到页面根节点 | 空白收口明确请求焦点回到重新出现的同一张 Card；翻页或切视图仍尊重新导航控件，不强行抢回。 |
| 日期选择器的五个日期外观相同，焦点移开后看不出当前页 | 当前选项持续使用 `aria-current="date"` 和轻量 Lemon Foam 色块；焦点只表示下一步操作，当前态表达正在看的页面。 |
| 应用跨过午夜后，页面仍把昨天称为“今天” | 在前台跨过本地午夜，或窗口重新获得焦点 / 可见性时，只刷新相对日期和“今天”入口；当前页面与操作现场不被系统搬动。 |
| 随手页打开日期选择器时，最近日期仍被标成当前页 | 随手页没有日期当前态；最近浏览日期只作为键盘默认焦点，不使用 `aria-current="date"`。 |
| 本地内容读取重试后按钮消失，焦点掉到页面根节点 | 重新打开成功后回到捕获输入；若读取仍失败，焦点回到重新出现的重试按钮。 |
| 日期页已经平移，底部输入的新 Card 仍按固定坐标出生并落在视野外 | 先复用目标时段中当前完整可见的开放槽位；时段完全离开视野时只平移足以露出新 Card 的距离，创建与视口结果共用一次 Undo。 |
| 用快速语法把 Card 放到另一日期页，后来翻过去却发现它落在那一页保存视野之外 | 异页捕获读取目标页会话 viewport 选择落点，并记住最新一张尚未看过的 Card；不移动当前页，用户真正翻到目标页时才做必要的最小露出。 |
| 在总览底部记下一张 Card，返回之前平移过的画布却看不见它 | 捕获保持总览现场；返回画布时消费同一条待露出信息，只移动足以看见新 Card 的距离。 |
| Inspector 把 Card 改到一个曾经平移过的日期页，详情跟过去但 Card 本身不可见 | 自动放置读取目标页会话 viewport；目标时段不在视野内时最小幅度露出 Card，保持页面、Card 与 Inspector 是同一个现场。 |
| 日期页面控件有 `aria-label`，但外层仍是没有语义的普通 `div` | 页面入口使用命名 `navigation` landmark；不增加任何可见标题或容器。 |
| 原生应用已有 citroam 图标，Web 开发预览仍显示浏览器默认页签图标 | Web favicon 直接复用原生 SVG 图标源，不复制或发明第二套品牌资产。 |
| 用户有意保留 Area 名称“新区域”，以后每次打开仍被整段全选 | 全选资格绑定本次新建的 Area 身份并只消费一次，不能仅靠文字内容猜测它仍是占位名。 |
| 中文用户自然写下 `买牛奶#今天` 或 `买牛奶！高`，候选却因为 marker 前没有空格而不出现 | 快速语法识别 marker 本身，不把分隔空格当成使用前提；候选、选择、提交和 styled token 分离对有无空格保持一致，无效片段仍保留为标题。 |

因此，后续设计评审优先问“是否减少了误解和维护成本”，而不是“是否增加了更多管理能力”。

### 当前收口重点

补充基线（2026-09-04）：前文若仍以“画布、总览与对话三个一级视图”描述旧实现，以本句为准——画布与总览是一级视图，Agent 只在画布上按需挂载为覆盖面板；它通过 Tauri sidecar 调用真实 DeepSeek Harness，收起后不保留可交互 DOM。更早段落中“原生对话视图仍需接入”的措辞属于历史快照，不是当前发布状态。

当前状态覆盖（2026-09-04）：本节前方若出现“画布、总览与对话只挂载当前一级视图”“进入对话后由独立输入替代捕获栏”或“原生对话视图仍需完成接入”等表述，均只用于保留历史验收上下文；实现与评审统一采用“画布 / 总览两个一级视图 + 画布内覆盖 Agent 面板”的模型。面板打开时画布、日期导航和普通捕获栏仍在背景可见，收起后只移除面板的可交互 DOM。

说明：本节上方保留的 370 项、374 项、376 项、377 项、387 项、392 项、394 项、399 项、401 项、416 项、421 项与 436 项描述属于早一轮历史快照；当前设计基线以文档开头的 440 项为准。窄窗口首次日期页的安全视口只改变内存中的观察位置，不改变 Card 数据或 Undo 历史；fit 使用已经测量的舞台高度，不重复扣除浮动捕获栏空间，时段标签则通过反向缩放保持屏幕可读。

当前不增加新的功能面，只继续守住四个容易破坏“随手用”体验的边界：

1. **点击与拖动分离**：Card、Area 空白轻点、鼠标或触控的画布空白收口、触控平移、移动 / 缩放把手，以及 Space + 左键和中键平移仲裁已经落地；所有移动手势在 4px 内不改变现场、不保存，越过阈值后即使回到原点也不误开详情。未形成平移的空白点击或轻点则提交草稿、收起详情或就地编辑并恢复原对象焦点。真实浏览器和触控设备仍需确认合成 click、pointer capture 与系统手势表现一致。
2. **缩放不丢观察点**：加减按钮使用舞台中心，修饰键滚轮使用指针位置，双指使用两指中点；没有净变化的视口命令保持安静。
3. **多反馈共存**：保存失败、异页捕获结果与撤销继续共享捕获栏上方的一条轨道，空间不足时自然换行；仍需在 760×560 真实窗口确认文字、按钮和捕获栏互不遮挡。
4. **真实窗口验收**：自动化负责行为回归，Tauri 窗口负责确认像素、截断、悬停、动画、焦点与真实 pointer 序列。启动成功不等于视觉和交互验收完成。
这四项属于当前版本的发布收口，不是引入新视图或新任务模型的理由。

### 自由，但不迷路

citroam 不用自动整理换取秩序，而用三个安全出口承担自由画布的熵：

1. “看全本页”看见当前页的完整空间，包括日期边界之外的未完成 Card。
2. 总览稳定列出每张未删除 Card，不受画布位置和重叠影响。
3. 搜索先找到内容，再切页、移动视口、提升目标层级并强调一次。

安全出口不能自动搬运、收拢或重新排列 Card。它们只恢复可见性，空间决定仍然属于用户。

```text
├────────────────────────────────────────────────────────────────────┤
│                 [随手页]  ‹  [今天 · 8月26日  日历]  ›             │
│                                                                    │
│                                                                    │
│          随时     Card      Card                                  │
│          上午          Card                                       │
│          下午     Card                                            │
│          晚上                 Card                                │
│                                                                    │
│              [+  放进今天…             #日期 !优先级  ↑]            │
└────────────────────────────────────────────────────────────────────┘
```

打开“对话”后，标题栏、页面导航、画布和普通捕获栏保持在背景；右下角只叠加一个轻量的原生对话面板：

```text
┌────────────────────────────────────────────────────────────────────┐
│ citroam     画布 / 总览        对话  搜索  保存状态         主题     │
├────────────────────────────────────────────────────────────────────┤
│                                                   ┌───────────────┐ │
│                                                   │ 你：把报销…    │ │
│                                                   │ 好，已处理  撤销│ │
│                                                   │ [说一句…    ↑] │ │
│                                                   └───────────────┘ │
└────────────────────────────────────────────────────────────────────┘
```

层级只有：

1. 标题栏：品牌、画布 / 总览、画布工具层对话入口、搜索、保存、主题。
2. 页面导航：仅在画布视图出现，包含随手页、前一天、日期复合按钮、后一天、按需出现的“今天”。
3. 工作区：当前页面中的 Card 与可选 Area。
4. 反馈轨道：只在有异页结果、撤销或保存失败时出现在捕获栏上方。
5. 捕获栏：在画布与总览中固定在底部，负责普通 Card 捕获与页面内快速操作；对话打开时仍保留，不与对话草稿混用。
6. 对话面板：按需覆盖当前画布，拥有自己的输入、回执与临时会话状态，但不改变一级视图。
7. Inspector 与其他临时浮层：按需出现。

页面导航不是数据管理器。用户永远不会看到“新建日期页”“删除页面”“折叠日期”或页面数量。

### 图标、提示与文字层级

工具的轻盈感不能建立在“让用户猜”或“把字做得很小”上。

- 有清楚文字标签的按钮不重复添加解释。
- 常驻纯图标，或在窄窗口隐藏文字后变成纯图标的按钮，使用原生桌面悬停提示；当前范围是主题、前一天、后一天、缩小、放大、画布与总览的完成圆圈、搜索、“看全本页”和“新建区域”。“对话”作为画布工具入口应优先保留文字标签，不伪装成难猜的 AI 图标。
- 提示与 `aria-label` 表达同一个动作。主题按钮描述下一步结果，例如“切换到深色模式”，而不是只写“主题”。
- 关闭浮层和 Area 尺寸把手依靠所在上下文和可访问名称，不机械铺满 tooltip；完成圆圈直接影响 Card 状态且图形可能被误认成选择控件，因此统一提示“完成”。
- 日期主标签至少 12px；Inspector 字段与具体时间、时段按钮、快速语法说明、总览元数据与数量、搜索结果上下文、日期选择和拖放反馈至少 10px。
- 搜索快捷键、缩放百分比、eyebrow 等不承担唯一语义的辅助信息可以使用 8–9px，但必须有邻近的清楚标签或图标。

这次调整不扩大控件尺寸体系，也不把标题栏改成带永久文字的传统工具栏；目标只是让现有动作无需试错。

## 打开与页面状态

### 默认状态

- 每次启动直接打开今天。
- 捕获栏自动聚焦。
- 即使今天没有 Card，也显示完整日期页，而不是创建向导。
- 空日期页只显示时段画布、页面导航和底部捕获入口，不增加额外空状态文案。不要出现“这一天还是空白的。想到什么，直接放下来”一类解释句。

### 翻页

- 前一天与后一天是最短路径。
- 日期标题与日历提示组成一个完整的复合按钮，也是唯一日期选择入口；不要再在旁边放一个作用相同的独立日历按钮。
- 日期标题使用两行互补信息：今天 / 明天 / 昨天放在 eyebrow，主标题显示月日与星期；其他日期把星期放在 eyebrow，主标题只显示绝对日期。跨年时绝对日期补年份，星期在整个按钮中始终只出现一次。
- “今天”只在有返回价值时出现。
- 翻页不改变 Card、不写 Workspace、不产生 Undo。
- 手动翻页表示离开旧页面：如果旧 Card Inspector 中有有效草稿，先提交一次，再关闭 Inspector。新页面不能继续显示上一页 Card 的详情。
- 导航动作先比较目标与当前 `pageKey`。目标相同时不构成翻页：保留 Card / Area Inspector、draft、视口和页面内容，不播放过渡。日期选择器内部的当前日期选项会随浮层消失，因此关闭后回到唯一日期按钮；仍存在的随手页按钮被再次点击时保留自身焦点。
- Card 在 Inspector 中改日期不是普通浏览：Card 原子移动后页面跟随到目标日期或随手页，并保持当前 Inspector。搜索与总览定位也只携带被明确定位的目标 Card，不携带旧页面选择。
- 每个日期页在当前会话中保留自己的视口位置；翻页只切换视觉页面，不因为恢复视口而产生保存。
- 如果当前来自已经平移很远的随手页，目标日期页还没有自己的会话视口时，首次打开使用按舞台尺寸计算的安全日期场景视口；这样日期场景不会整体落在屏幕外而被误认为空白。该日期页后续再被打开时，才恢复它自己的会话视口；这一步不写 Workspace、不产生 Undo。
- 页面内容使用 180ms 水平位移与淡入，方向与翻页方向一致。

跨过本地午夜不是一次翻页动作。应用在前台跨日，或从后台重新获得窗口焦点 / 页面可见性时，只更新“今天 / 昨天”等相对称呼、日期选择器内容和“今天”返回入口。当前 `pageKey`、Card 坐标、会话视口、Inspector 与未提交草稿全部保持原样；这次刷新不写 Workspace、不创建 Undo，也不把用户强行带到新的一天。

日期选择器中的快捷日期围绕当前正在查看的日期展开；今天继续通过相对称呼辨认。真实日期页中，正在查看的选项持续使用 `aria-current="date"` 与安静的 Lemon Foam 当前态，键盘焦点移到相邻日期时，当前页标记不能随之消失。随手页不是日期页：选择器可以把最近浏览日期作为默认焦点，但不能把任何日期标记为当前页。用户跳到远期日期后，再打开选择器仍然看到附近几天，而不是永远回到今天附近。原生日期输入只负责跳转，不把产品变成月历。

### 视图与编辑现场

“画布 / 总览”、页面导航、对话面板和搜索结果不是互不相干的按钮，它们都可能改变用户正在面对的操作现场。先确认目标上下文与当前上下文不同，真实切换才遵循固定顺序：

1. 提交当前合法的 Card、Area 或就地标题 draft。
2. 结束只属于旧现场的 Inspector 与编辑态。
3. 切换页面或一级视图。
4. 只有动作明确指向某张 Card 时，才在新现场打开该 Card 的详情。

具体边界：

- 手动翻页不携带旧 Card Inspector。
- 重复选择当前日期或当前随手页不属于手动翻页，不结束 Card / Area Inspector 或草稿。
- 画布 / 总览切换都不携带 Card Inspector、Area Inspector 或 Card 就地编辑；对话面板的会话状态按本节规则保留。
- 离开随手页前提交 Area 改名并关闭 Area Inspector。
- 搜索进入已完成结果时进入总览已完成状态，并清除旧画布详情。
- Inspector 中修改 Card 日期、撤销该日期变更、搜索定位和总览定位可以携带被明确操作的目标 Card；它们不能顺便携带另一张旧 Card。

这套规则不增加确认步骤。有效草稿安静提交，无效空标题留在原数据或按既有取消规则处理，用户不会因为导航被额外弹窗阻挡。

### 前一天遗留

当前日期的前一天有未完成 Card 时，在画布左上显示安静书签：

> 前一天还留着 3 张

它只回答“那里还有内容”。点击后翻回前一天，不自动移动、不弹确认、不显示红色。

## 日期页

### 页面是画布，不是嵌套卡片

日期页使用固定的工作区几何边界，但不渲染成一张额外的日期卡片：

- 不能移动、缩放、收起或删除。
- 不展示选择描边和容器把手。
- 不进入 Workspace 数组。
- 顶部页面导航是唯一的日期标签和日期选择入口。
- 工作区不重复显示日期 Header、数量标签或日期容器背景。
- 日期页的技术边界只服务于新 Card 的建议位置、Inspector 自动放置、拖放时段判断和“看全本页”；不限制用户手动拖动。

这样用户看到的是“正在使用这一天”，而不是“在一张日期卡片里继续操作”。

### 柔性时段

页面内部自上而下只有四块：

| 区域 | 含义 | 页面标签 |
| --- | --- | --- |
| 随时 | 只确定了日期 | 随时 |
| 上午 | 适合上午 | 上午 |
| 下午 | 适合下午 | 下午 |
| 晚上 | 适合晚上 | 晚上 |

时段采用不完全对齐的柔软背景带，而不是表格行：左右边界略有差异，围栏之间留出约 24px 的垂直呼吸空间，并用轻边框帮助快速辨认，避免传统日历与排班表气质。每个背景带只显示图标和时段名称，不再添加“慢慢醒来”一类气氛文案。画布缩放时，标签组使用与世界缩放相反的比例，维持接近正常屏幕字号；这只调整标签的视觉可读性，不改变围栏几何、命中区域或 Card 坐标。文字、图标、边框和相对位置共同表达语义，不只依赖颜色。

Card 在区域内仍自由使用 x/y，也可以停在围栏间隙或外围的自由画布。放在围栏外不会离开日期页，只会把时间精度放宽为“随时”。产品不按优先级、开始时间或创建时间重新排列。

### 日期页拖动

1. pointerdown 记录 Card、起点、日期和时间精度。
2. pointermove 直接改变 DOM transform，不写 React Workspace。
3. Card 中心经过时段背景，决定潜在 period；当前围栏轻微高亮，并显示目标语义与最终吸附位置的幽灵预览。经过间隙或外围时潜在 period 为空，反馈回到“随时”。
4. 手动拖动不做页面收边，Card 可以离开所有围栏甚至离开日期画布的可视范围；只有新建 Card 和 Inspector 自动放置使用页面几何作为建议范围。
5. pointerup 一次提交坐标、pageKey 与 timeConstraint；若潜在 period 存在，坐标吸附到该围栏的可放置范围并播放 200ms 的回弹。
6. 同一具体时间所属时段内移动保留 start/end；跨到其他时段或离开所有围栏才清除具体时刻。

这不是自动排程，只是用户直接摆放产生的明确时间含义。离开围栏代表用户暂时不想做更细的时间承诺。

拖动的空间规则需要保持可预测：

- 日期页的视觉边界不是裁剪层，也不拦截 Card 的 pointer 事件。
- Card 可以被拖到四个围栏之外；释放后仍留在当前日期页，只把时段放宽为“随时”。
- 只有新建 Card、Inspector 自动放置和“看全本页”使用日期几何作为建议范围。
- 新建 Card 先从目标时段的固定候选中筛选当前 viewport 内完整可见的空槽，再用安全可见槽补足横向平移和窄窗口；没有可见空槽时允许最新 Card 回绕叠放，但不把它推到屏幕外。
- 如果用户纵向平移到目标时段完全不可见的位置，新建 Card 仍留在正确时段，视口只移动足以让它避开顶部导航与底部捕获栏的距离。Card 与视口作为一次创建进入同一 Undo；撤销后同时恢复创建前内容和观察位置。
- Inspector 把未完成 Card 移到另一日期页时使用目标页会话 viewport 执行相同计算；必要的最小视口移动先写入目标页会话现场，再跟随 Card 与 Inspector 进入目标页。已完成 Card 不改变隐藏画布现场。
- 围栏高亮、幽灵位置和最终吸附使用同一套几何计算，不能出现“预览在这里、落下在另一处”。
- 吸附只在释放瞬间发生一次，不能在拖动途中偷偷改写 Workspace，也不能为了防重叠自动推开其他 Card。

预览层只在活动拖动会话中存在，使用 transform 与 opacity，不进入 DOM 的持久卡片层，也不更新 Workspace。围栏不能在 Card 只是经过时改变数据。

### 看全与找回外围 Card

日期页边界是时间场景，不是 Card 的硬边界。因此“看全本页”不能只看固定日期场景：

- 计算范围时合并日期场景边界与当前页全部未完成 Card 的包围盒。
- 随手页合并未完成 Card 与 Area。
- 随手页既没有未完成 Card 也没有 Area 时禁用入口；即使通过程序触发也直接结束，不改 viewport，不触发保存或 Undo。
- 计算出的目标视口与当前可见视口一致时直接结束，避免无意义的“正在保存”闪动。
- 不因为 Card 在很远处就自动把它移回来。
- 从搜索或总览定位时先切到 pageKey，再移动视口，最后临时把目标 Card 提到最前并强调一次。
- 临时视觉提升不改持久 zIndex；只有用户真正拖动 Card 才更新堆叠顺序。

即使两张 Card 完全重叠，被定位的那张也必须可见和可操作。

## 随手页

随手页负责“现在还不想决定”。

- 没有日期标题和时段背景。
- 普通捕获创建无日期 Card。
- 新 Card 使用随手页当前可见 viewport 与 zoom 的有限槽位；窗口或缩放改变时重新计算容量，优先复用没有被开放 Card 占用的槽位，全部占用后才回绕叠放，最新 Card 始终在眼前。
- Card 可以无限自由摆放。
- 允许创建可命名 Area。
- 背景只有低对比轨迹线与少量品牌形状，不持续运动。

空随手页不显示专门的标题、段落或操作说明。轨迹背景和底部捕获栏保持可见，用户可以直接开始。

Area 只是一块视觉托盘，不拥有项目状态、进度和自动行为。它只在随手页出现，避免日期页同时拥有两套空间语义。

Inspector 中如需解释，只使用直接说明：“区域只表示空间范围。移动区域不会带走卡片。”不使用“轻轻圈住念头”一类品牌化长句。

Area 改名使用本地 draft：输入时不逐字保存，失焦或 Enter 时一次提交并可撤销，Escape 放弃未提交的改名。新建后的首次聚焦完整选中默认名称“新区域”，用户直接输入即可替换；再次打开已有 Area 时只聚焦，不自动全选，避免误覆盖真实名称。Enter 是“保存但继续编辑”，因此输入保持焦点；点击或 Tab 到别处形成的普通 blur 只提交，不把焦点拉回 Inspector。用户写完名称后可以直接抓住 Area 移动或缩放；手势开始时先提交合法名称，再用最新 Workspace 保存几何。Area 内部的空白仍是可平移的画布，只有移动和缩放把手占用专门手势。三种手势共用 4 CSS px 意图阈值：把手的轻点抖动不移动、不缩放、不保存，也不增加 Undo；越过阈值后才进入变形状态。

新建 Area 是一个“放到眼前”的动作。创建时读取随手页当前可见 transform，把屏幕内的安全内边距换算为世界坐标；默认尺寸如果大于当前可见世界范围，仍优先保证名称区和移动把手可见。连续创建使用小幅、确定性的候选错位，先复用没有被现存 Area 占用的偏移，全部占用后再回绕；删除旧 Area 后不能因为沿用历史数量而与剩余 Area 完全同坐标，也不能继续向屏幕外累加。创建后沿用 220ms 的进入动效并直接聚焦、全选默认名称，不自动执行“看全本页”。

Area 控件遵守“按需显现”：鼠标悬停、Area 已选中或键盘焦点进入时，边界和缩放把手使用同一状态；其他时间保持安静。这样键盘用户不会聚焦到透明控件，也不会为了可访问性把画布长期变成工具面板。

显现之后还必须让人感觉它们真的可以操作。移动把手以 140ms 过渡背景与文字色，按下缩至 0.98；缩放把手同时过渡透明度、背景与文字色，悬停时从托盘上浮现为 Surface，按下缩至 0.94。两者的按压时长均为 90ms。这里只补反馈，不改变 32px 最小操作高度、4 CSS px 手势阈值、pointer capture 或最终几何。

Area Inspector 也遵守“明确进入”：新建或点击 Area 后直接聚焦名称，减少一次额外点击；键盘只是 Tab 到移动或缩放把手时不自动打开详情。关闭或 Escape 回到该 Area 的移动把手，删除则回到捕获栏。

Card 进入 Area 的视觉范围不会建立正式成员关系，Area 移动或缩放也不带走 Card。空间重叠就是全部语义。`areaId` 只作为 v3 存储与旧数据迁移的兼容字段存在，不应在新交互中演化成项目归属。

## 捕获

### 默认规则

| 当前页 | 没有时间 token 的结果 |
| --- | --- |
| 日期页 | 进入该日“随时” |
| 随手页 | 保持无日期 |
| 总览 | 沿用最近打开的画布页 |

捕获栏的 placeholder 只命名动作与目标页面：今天 / 明天 / 昨天分别使用 `放进今天...`、`放进明天...`、`放进昨天...`；其他日期直接写出月日，跨年时补年份，不能只写星期而让目标含糊。随手页固定使用 `放进随手页...`。它不解释用户为什么尚未分类，也不替用户描述心理状态。

按 Enter 后：

1. Card 立即创建。
2. 输入框清空并保持焦点。
3. 在日期页中，Card 进入目标页会话 viewport 内的时段候选槽；在随手页中，Card 进入当前可见 viewport 的候选槽。两者都先复用没有被开放 Card 占用的位置，所有候选都占用后才回绕叠放，而不是按历史总数继续排布或精确盖住仍存在的 Card。异页捕获不切页；用户之后真正翻到目标日期时，最新一张尚未看过的 Card 必须以最小视口移动进入眼前。总览捕获也不自动切换视图，返回画布时遵守同一规则。
4. 新 Card 使用 220ms pop 动效。
5. 不打开详情，不切换页面。

### 快速语法

| 输入 | 结果 |
| --- | --- |
| `#今天` | 今天随时 |
| `#明天` | 明天随时 |
| `#今天上午` | 今天上午 |
| `#今天下午` | 今天下午 |
| `#今天晚上` | 今天晚上 |
| `#今天14:00` | 今天 14:00 |
| `!高` / `!中` / `!低` | 可选优先级 |

输入 `#`、`!` 或 `！` 后立即出现菜单。完整 token 不作为普通标题文字渲染；确认后变成独立胶囊，用户可以单独移除。

候选菜单描述直接说明结果，例如“高优先级”“中优先级”“低优先级”，不使用“可以轻轻放在后面”一类情绪化解释。

用户不必先点候选，也不必在标题与 marker 之间或 token 之后补空格。`买牛奶 #今天` 与 `买牛奶#今天` 是同一种输入，`整理资料 !高`、`整理资料!高`、`整理资料！高` 也必须一致：marker 一出现就展开候选，确认后只把合法 token 分离为胶囊，相邻中文标题保持原样。提交时再做一次确定性解析，即使精确候选仍展开，一次 Enter 也直接创建；token 尚未写完整、用户已用方向键选到另一个候选或还没有标题时，Enter 才确认候选。无效 token 保留为普通标题，不能因为 marker 紧接文字就被误删。中文输入法 composition 期间不提取、不提交，也不阻止 Enter 等输入法按键的默认行为；结束后才更新候选。用户移除一个 token 后，消失的 token 按钮把焦点交回捕获输入，继续输入不需要再点一次。
组合输入结束时，已完成的 token 会在一次解析中恢复为独立胶囊，即使输入法同时留下尾随空格；普通键入仍保留完整 token 的候选菜单，避免用户失去选择机会。

快速候选不是常驻工具栏。用户点击捕获栏外时只收起候选，不清空文字或已选 token；重新聚焦仍含有效 `#` / `!` 片段的输入框时，候选按当前片段重新出现。候选展开时，Escape 只收起候选并保留输入；即使 Card Inspector 同时打开，也不能顺带关闭 Inspector。这样一次 Escape 只结束最贴近用户的一层，临时层跟随注意力，也不要求用户为了“关闭菜单”先删除正在写的内容。

优先级只使用“无 / 高 / 中 / 低”一套用户语言。内部兼容值可以继续是 `normal`，但界面不能在“中”和“普通”之间来回切换。

时间 token 可以覆盖当前页，但不强制跳走。例如用户在今天输入 `#明天`，Card 被放到明天，底部只显示“已放到明天”。

## 画布原生 Agent

本节描述 Agent 作为画布原生操作层的产品基线与发布门槛。Agent 不是第三个一级视图，也不是独立聊天产品；它覆盖当前画布，使用真实 DeepSeek Harness 把一句明确的话转换为一次可验证的 Workspace 操作。当前工程已有结构化意图、消歧、确认、回执、撤销、会话状态保留、导航边界与失败 no-op；真实 Harness 构建、sidecar 生命周期、细部视觉与真实 Tauri 窗口仍需按本节收口。设计重点不是让 citroam 看起来“拥有 AI”，而是让用户在不想打开详情、逐张点击时，可以像说一句普通话那样完成一次维护。

### Harness 运行契约

生产实现不是本地规则解释器的伪装，而是一个由 Tauri 管理的真实 DeepSeek Harness SDK sidecar：

```text
打开面板（不启动模型）
  ↓ 用户发送请求
Rust 启动 dsh --profile sdk
  ↓ initialize（一次）
稳定 session 内 session/prompt
  ↓ session.event / session.status
提取 citroam_apply 的 canonical JSON
  ↓
本地 AgentIntent policy → Workspace reducer → Undo
```

- sidecar 的 stdout 只承载 JSON-RPC；stderr 仅用于诊断。`initialize` 完成前不发送 prompt，同一进程内复用 session，退出时发送 `shutdown` 并兜底回收子进程。
- `agent/citroam.cordis.patch.yml` 在 SDK profile 上禁用 bash、PowerShell、文件系统、网络、子 Agent、计划、目标、工作流、todo、编辑器和命令工具，仅插入 `citroam_apply`。该工具只回传模型提出的 JSON，不直接触碰 Workspace。
- 面板向 Harness 发送压缩后的上下文：当前日期页、选中 Card、总览状态，以及未删除 Card 的 id、标题、状态、时间约束、优先级和所属 pageKey。坐标、Area 几何、viewport、备份与聊天历史不发送。
- API Key、模型和 Harness 根目录由应用设置统一管理。API Key 只保存到系统 Keychain，绝不写入仓库、Workspace、备份或日志；模型与 Harness 根目录只保存非敏感配置。首次运行也兼容 `DEEPSEEK_API_KEY`、`CITROAM_DEEPSEEK_MODEL` 与 `CITROAM_HARNESS_ROOT` 环境变量，但只在没有已保存设置时作为回退。未设置运行目录时由 Tauri 为 App 进程创建并在退出时清理专属临时目录；设置 `CITROAM_HARNESS_HOME` 后保留用户指定目录。Harness 未构建、密钥缺失、provider 失败、超时或 JSON 无效时，界面显示失败回执，Workspace 不变。

### Harness 模块与 citroam 映射

citroam 消费 Harness 的 SDK 能力，不修改 `deepseek-harness` 源码。Harness 的 Cordis 插件树仍由 Harness 负责组合，citroam 只通过 profile 与 patch 注入最小的本地工具边界：

| Harness 概念 | citroam 实现 |
| --- | --- |
| Cordis plugin tree | sidecar 内由 SDK profile 与 citroam patch 组合；模型、工具、会话和传输仍是 Harness 插件。 |
| profile | `dsh --profile sdk`，由 Tauri 作为进程外 JSON-RPC 运行时启动。 |
| patch overlay | `agent/citroam.cordis.patch.yml`，禁用与日常 Card 无关的通用工具，只插入 `citroam_apply`。 |
| LLM adapter | Harness 的 DeepSeek official provider，模型名与密钥来自应用设置。 |
| tool registry | 仅注册 `citroam_apply`；它回传结构化 `AgentIntent`，不直接写 Workspace。 |
| session event | Rust 监听 SDK 的 `session.event`，提取工具调用与 Agent 回执。 |
| agent status | Rust 等待 `session.status=idle`，再把 canonical JSON 交给本地 policy。 |
| local authority | citroam 的 reducer、policy、并发现场保护与 Undo；最终决定目标、坐标和是否提交。 |
| SDK transport | Tauri 管理 Node sidecar 的 stdin/stdout newline-delimited JSON-RPC，stderr 仅用于诊断。 |

这层映射保持“模型负责理解、产品负责写入”的边界：Harness 可以替换 provider、工具和会话实现，但不能绕过 citroam 的本地数据权限；citroam 也不把 Workspace、备份、Area 几何或坐标交给模型。

### 应用设置

设置是统一的模态浮层，不是第三个一级视图，也不改变画布、总览或 Agent 的本地优先边界。标题栏固定提供齿轮入口；Agent 面板的标题栏也提供“打开模型设置”直达 Agent 分类。设置分为三组：

- **外观**：浅色 / 深色主题。主题立即预览并保存到本机偏好，下次打开应用沿用；不改变 Workspace 内容。
- **Agent**：显示当前 provider、模型名称、Harness 路径和密钥是否已配置。密钥输入框永不回显已保存值，留空保存代表“不改动现有密钥”；只有用户明确清除才删除系统凭据。`保存` 写入非敏感配置并结束旧 Harness 进程，下一次对话使用新配置；`保存并测试` 在保存后启动 Harness、执行 `initialize` 并回收进程，不发送用户任务，不把“启动成功”夸大为已经完成一次模型请求。
- **数据**：继续提供本地 Workspace JSON 导入 / 导出。导出只包含 Workspace，绝不包含 API Key、模型凭据或 Harness 会话；导入前使用应用内确认层，仍可通过 Workspace Undo 撤销。

设置浮层遵循与其他浮层相同的焦点与动效协议：打开后焦点留在当前分类，Tab 不离开面板，Escape 关闭并回到触发按钮；面板只使用 180ms 的透明度 / 轻微位移动效，`prefers-reduced-motion` 下立即出现。窄窗口改为单列布局，分类仍保持可见，API Key 状态只显示“已配置 / 未配置”与来源，不泄露字符内容。

```text
进入对话 → 说一句 → 看见真实结果 → 继续生活
```

### 角色与出现方式

Agent 是画布工具层的一等能力，以右下角轻量面板覆盖当前画布。它不是第三个一级视图，也不是需要单独维护的聊天空间：

- 画布工具层始终提供“对话”入口；点击入口或按 `⌘ J / Ctrl J` 打开面板并把焦点放到输入框，画布、时间围栏和 Card 保持可见。
- 应用启动、翻页、拖动和普通捕获不启动 Harness、不初始化模型、不发起网络请求；只有用户提交明确请求时才由 Tauri 按需启动 sidecar。
- 面板可以收起；收起只隐藏操作层，不清空当前会话，也不改变页面、视口或 Card。没有用户输入时 Agent 保持安静。
- 画布底部的普通捕获栏始终保持可见；它与对话输入使用独立 draft。从对话切回画布或总览时，两份 draft、对话历史、候选和待确认状态都留在当前应用会话中。
- 进入对话前若有一张明确选中的 Card，先把它的稳定 ID 交给对话上下文，再结束画布或总览 Inspector；视图卸载本身不能让“这个”失去指向。
- 画布、总览和对话共享同一个 Workspace；Card 的创建、移动、完成、恢复和定位结果都必须真实落到既有数据模型。
- Agent 从不主动弹出或抢回焦点；用户没有说话时，面板保持安静。
- 生产模型固定通过 DeepSeek Harness SDK profile 运行；Harness 未构建、密钥缺失、断网或失败时，本次请求明确失败且 Workspace 不变，普通捕获、画布、总览与撤销仍可用。

桌面面板沿用应用主工作区的布局与导航，不使用独立页面或悬浮纸片。输入、消息、候选、确认和回执在面板内形成清楚的纵向层级；760×560 时仍保留输入与主要回执的可见性，内容区域可独立滚动。触控版使用同一面板模型，窄屏改为贴边单列面板，不复制另一套会话。

Agent 面板只保留四个部分：

1. 面板标题与当前会话状态。
2. 必要时出现的当前上下文，例如“正在处理：报销”。
3. 短对话、候选与结构化动作回执。
4. 固定在工作区底部的输入与发送动作。

不使用机器人头像、角色插画、星光符号、AI 紫色、发光边框或不断跳动的思考装饰。用户文字略靠右，Agent 回应靠左，不为每句话套厚重聊天气泡。操作回执可以使用轻底色，但继续遵守现有圆角、边框与 `Juicy Utility` 色彩系统。入口与其他画布工具保持同等层级，不通过高亮、红点或未读计数制造压力。

### 最短交互状态机

对话一次只承载一个当前意图。每个状态都必须能被用户看懂，并能在面板收起、页面翻页或切到总览时不丢失现场：

```text
画布 + 对话面板（输入获得焦点）
  ↓ 发送
处理中（真实状态，不表演思考）
  ├─ 唯一目标 → 执行 → 回执（查看 / 撤销）
  ├─ 多目标   → 预览 → 确认 / 取消 → 回执或回到空闲
  ├─ 有歧义   → 一个最小问题 → 选择 → 继续当前意图
  └─ 失败     → 说明“画布没有变化” → 重试 / 修改输入
```

面板与总览或日期页面之间的切换是明确的上下文边界：用户切到总览、翻页或收起面板时，先提交合法 draft、结束不属于目标视图的 Card / Area 就地编辑，再显示目标视图。对话草稿、历史、候选和待确认状态保留在当前应用会话中，不漂浮到其他视图，也不写入 Workspace。Agent 为展示结果而定位到画布或总览时，保留当前回执与返回入口，避免用户刚发出的请求失去上下文。

- Agent 处理中输入可以继续编辑，但同一时刻只允许一个请求进入执行态；迟到的响应如果已失去目标或依赖的页面上下文，直接丢弃，不覆盖新现场。切换“画布 / 总览”或收起面板不构成失去上下文，也不能取消合法的执行中请求。进入候选或确认态后，先完成或取消当前动作，再继续发送。
- 请求执行期间允许用户继续拖动 Card / Area 或平移画布。手势提交时必须读取最新 Workspace，再只合并本次手势实际负责的字段；例如 Agent 修改标题后，Card 释放仍可更新坐标，但不能把标题写回旧值。
- “处理中”只在真实解析或执行期间出现，不增加人为延迟、打字机效果或循环跳点；动作成功以前不提前写入 Workspace。
- 回执是结果的一部分，最多一句短句和两个直接动作（通常为“查看”“撤销”）；完成后不追问下一步，也不把对话变成长列表。
- Escape 按最近层级收口：先取消候选或确认，再清空当前临时状态并回到对话输入；再次按下收起面板。普通捕获 draft、Card Inspector 与画布视口按各自协议保留。
- 预览、候选和错误都是临时界面状态，不写入 Workspace、不产生 Undo，也不能遮住确认框或把焦点送进背后的画布。

### 会话上下文

对话只理解用户眼前可以验证的上下文：

- 当前 pageKey 和日期语义。
- 当前明确选中的一张 Card。
- 当前总览状态。
- 为这次请求检索出的少量候选 Card。
- 当前应用会话中最近一次仍有效的对话目标。

存在选中 Card 时，面板明确显示“正在处理：Card 标题”。“这个”“它”“刚才那个”只在目标唯一且仍存在时生效；用户切换 Card、目标被删除或会话结束后，旧代词引用失效。多个同名 Card 必须显示日期、时段或完成状态帮助选择，不能靠模型猜测。

### 短暂记录窗口

对话记录只是帮助用户完成眼前动作的临时现场，不是需要维护的聊天档案：

- 当前会话最多保留最近 8 条消息；每条用户输入或 Agent 回执各算一条，新增消息从顶部淘汰最早消息。
- 对话消息区独立滚动；新消息或处理中状态出现后，自动把最新回执滚入可见区域，输入与主导航始终固定可达。
- Agent 处理中仍可以编辑下一句；同一时刻只允许一个请求执行，发送按钮在处理中禁用，下一句草稿不被清空或覆盖。进入候选或确认态后，先完成或取消当前动作，再继续发送。
- 收起面板、翻页或组件重新挂载时，当前会话中的临时记录与短上下文继续保留；应用重启后不恢复聊天时间线。8 条窗口之外的历史不写入 Workspace、备份或模型上下文。
- `prefers-reduced-motion: reduce` 下仍保持同样的可见结果与焦点顺序，自动滚动改为即时滚动，不播放平滑滚动动画。

### 支持的对话

Agent 只把自然语言翻译为现有产品动作：

- “明天下午交水电费”创建 Card。
- “把报销放到明天下午”移动唯一匹配的 Card。
- “这个做完了”完成当前明确选中的 Card。
- “把它改成下午三点”修改当前 Card 的时间精度。
- “把报销标记为高优先级”修改当前 Card 的优先级。
- “今天还有什么”“明天有什么任务”“周五有什么”展示对应日期的事实结果并提供“在总览中查看”；这类查询始终只读，不会因为结果为空而创建 Card。
- “今天完成了什么”或“周五完成了哪些任务”只展示对应日期的已完成 Card；有结果时说“今天有 N 张已完成”，没有结果时说“今天没有已完成的 Card”，不能把状态写成“未完成”。
- “把今天没做完的移到周五”预览一组 Card，确认后原子移动。

如果用户说“把报销放到那里”这类缺少明确日期或时段的维护句，Agent 只要求补充目的地并保持 no-op，不能把整句话误当成新的 Card 标题。

日期词按本地日历解释：`周五`表示即将到来的周五，`下周一`表示下一周的周一；不能因为当前星期已经接近目标日，或目标日早于今天，而额外跳过一整周。

### 时间意图先解析，后校验

自然语言里的时间只负责表达用户的意图，最终能否落地由本地规则决定。Agent 生成的 `TimeConstraint` 必须满足：

- 具体时刻使用合法的 `HH:mm`，并由 citroam 的统一时段映射决定它属于“上午、下午或晚上”；声明的时段与具体时刻不一致时拒绝执行。
- 口语时间允许自然空格，例如“明天下午 3 点”；解析后仍必须保留正确的下午语义与 `15:00` 精度，不能因为排版空格退化成凌晨或上午。
- 结束时间只有在同时提供开始时间时才有效，并且必须晚于开始时间；不接受只有结束时间或反向区间。
- 只有日期、只有时段或“随手页”仍然是合法的低精度意图，不要求用户补齐不必要的具体时刻。
- 校验失败不回退成猜测的日期或时段，不产生半张 Card、部分批量结果或 Undo；对话只显示“画布没有变化”，让用户修改原话后重试。

它不回答开放式人生咨询，不为用户生成一天的计划，不自动拆任务，不根据空间位置推断优先级，也不调用 citroam 当前 Card 模型之外的项目、目标或提醒能力。用户说“提醒我”时，Agent 只能明确创建带日期或时间的 Card，不能暗示产品会发送尚不存在的系统通知。

### 三种动作安全等级

| 等级 | 场景 | 交互 |
| --- | --- | --- |
| 直接执行 | 唯一目标、单张、可撤销 | 执行后回复短句，并显示“查看 / 撤销”。 |
| 预览确认 | 批量移动、批量完成或影响多张 Card | 显示动作、数量与目标摘要；确认后作为一个事务执行。 |
| 明确确认 | 删除、覆盖本地内容或其他破坏性操作 | 进入现有安全确认层，默认焦点为取消。 |

缺少必要信息或存在多个目标时，Agent 只问一个最小问题。例如：

> 找到两张“报销”，你指哪一张？

此时显示最多几个可辨认候选。用户选择前，Workspace、页面、焦点和 Undo 均不变化。不能为了让对话显得顺畅而猜一个最可能的目标。

### 结果必须回到 Workspace

对话不是第二套任务系统。Agent 的每个结果都复用现有行为：

- 新 Card 使用当前页面与 visible viewport 的空槽规则。
- 跨日期或移到随手页复用现有目标页放置与最小露出。
- 时段变化复用围栏语义和吸附位置，不由模型生成坐标。
- 完成复用画布或总览各自的离场和焦点协议。
- “查看”复用搜索与总览的定位机制：未完成 Card 回到所属画布并打开详情，已完成 Card 进入“总览 / 已完成”，不把用户带到不可见的画布详情。
- 单张修改和批量事务都进入同一 Workspace Undo；批量动作只产生一条 Undo。
- 除“打开 / 查看”本身就是用户意图，或用户点击回执中的“查看”外，创建、修改、移动、完成和恢复成功后留在 Agent 面板，不为了证明动作发生而自动跳走。

确认批量动作前，可以在当前画布上用半透明轮廓预览仍在当前页可见的目标位置。预览不写 Workspace；跨页目标在回执中按日期和数量说明，不为了展示预览擅自翻页。

### 回应语气

Agent 温和但没有人格表演。这里追求的是安静陪伴、尊重沉默和对日常动作的体贴，不模仿动画角色或建立吉祥物。

使用：

- “好，放到明天下午了。”
- “完成了。”
- “会移动 6 张 Card。”
- “找到两张‘报销’，你指哪一张？”
- “现在没有处理成功，画布没有变化。”

避免：

- “你好，我是你的智能任务管家。”
- “我来帮你规划高效的一天。”
- “太棒了，你今天效率很高。”
- “根据你的习惯，我建议……”
- “我已经智能优化了你的画布。”

没有结果时不硬凑建议；一次操作完成后不继续追问“还需要什么帮助吗”。结果超过三张时不在对话中铺成长列表，只显示数量、少量摘要和“在总览中查看”。

### 状态、错误与隐私

发送后使用真实的动作状态，例如“正在查找”“正在移动”，不使用人为延迟、打字机动画或表演思考的跳点。流式文字可以自然出现，但动作只有在本地 policy 校验通过并完成原子提交后才显示成功。

Agent 的执行链路固定为：

```text
用户语言
  ↓
结构化 AgentIntent
  ↓
本地目标解析与 policy 校验
  ↓
预览、确认或直接执行
  ↓
既有 Workspace action
  ↓
可见结果与 Undo 回执
```

模型没有 repository、Workspace reducer 或坐标写入权限。schema 无效、目标已变化、网络失败或执行冲突都必须整体 no-op，并直接说明“画布没有变化”。

### 并发现场保护

Agent 是异步操作层，但 Workspace 仍只有一个真实来源。任何可能与用户手势交错的提交都遵守以下规则：

- `pointerup`、Agent 执行和视口保存读取提交时的最新 Workspace，而不是开始手势或请求时捕获的旧快照。
- Card 拖动只写入最终坐标与由围栏命中的日期 / 时段；标题、备注、优先级、完成状态和其他并发修改必须保留。
- Area 移动 / 缩放只写入本次手势负责的几何字段；同时发生的 Card 或 Workspace 修改不能被覆盖。
- 只更新视口的平移 / 缩放不得把旧的 Card、Area 或草稿写回 repository。
- 普通捕获、文字 draft、Card / Area 手势、Agent action 与卸载前的防抖视口写入共用一条 FIFO 串行保存队列；提交时从最新 Workspace 生成快照，较新的状态不能绕过队列，卸载也只能把待冲刷视口追加到队列，不能直接写 repository。
- Agent 预览、迟到响应或目标已经变化时，无法安全合并就整体 no-op；不得部分执行、消费 Undo 或留下临时数据。

这条规则是发布门槛的一部分。自动化测试必须覆盖“Agent 请求进行中 → 用户开始手势 → Agent 先完成 → 用户释放手势”以及反向顺序，验证内容字段与几何字段都被保留。

只发送完成当前请求所需的文字与压缩后的 Card 元数据，不发送完整 Workspace、画布坐标、Area 几何、备份或历史会话。面板首次发出请求前，用一层直接说明交代 DeepSeek provider、数据去向与网络依赖。普通捕获、编辑、拖动、搜索、总览、完成与本地备份继续离线工作。

对话历史默认只保留在当前应用会话的易失状态中。重启后不恢复聊天时间线，也不把用户说过的话混入 Card 或备份；真正完成的 Card 修改仍按正常 Workspace 规则持久化。

## Card

### 视觉

Card 是一张饮料标签，不是缩小表单：

- 248px 基础宽度。
- 不对称 18px 圆角。
- 轻量 2px 偏移阴影。
- 左侧柠檬色完成气泡。
- 标题最多三行。
- 时间、优先级、备注只在存在时出现。
- 时间标签可以使用橙色帮助扫描；优先级与备注保持中性色，不因排列顺序获得额外紧迫感。

所有 Card 使用一致基础色，不随机染色或旋转。自由感来自空间与交互，不来自视觉噪声。

### 时间元数据

Card 上的时间信息随所在视图变化，避免重复页面已经表达的内容：

| 场景 | `anytime` | 柔性时段 | 具体时刻 |
| --- | --- | --- | --- |
| 日期页 Card | 不显示 | `上午` / `下午` / `晚上` | `14:00` / `14:00-15:00` |
| 总览 / 搜索 | 完整日期 | 完整日期 + 时段 | 完整日期 + 具体时刻 |

“完整日期”仍然服从上下文减法：目标日期与当前日期同年时显示月日，跨年时补充年份。日期页顶部使用同一规则，既不让今年的每一天都背着冗余年份，也不把明年的 Card 伪装成今年。

日期页顶部已经是唯一日期标题，因此 Card 不显示“今天 上午”或“8月28日 14:00”。信息减法只影响呈现，不改变 `timeConstraint`。

### 操作

| 动作 | 结果 |
| --- | --- |
| 单击 | 打开 Inspector |
| 拖动 | 改变页面内任意位置；日期页可改变时段，也允许越出视觉边界 |
| 双击标题 | 就地编辑 |
| 完成圆圈 | 完成 |
| Escape | 关闭或取消 |

删除是独立的确认动作；已删除 Card 不参与完成 / 恢复切换，撤销或本地备份恢复是唯一找回路径。

拖动时可以轻微放大、加深阴影与产生最多 0.6° 倾斜，但指针坐标不做补间。释放后 200ms 回到稳定外观。

### Inspector

只包含：

1. 标题。
2. 日期。
3. 优先级。
4. 时段与按需出现的具体时刻。
5. 备注。
6. 删除。

日期修改具有空间结果：新日期意味着换页，清空日期意味着移到随手页。从总览修改未完成 Card 时，产品主动回到目标画布页并保持详情打开，避免用户以为内容消失；已完成 Card 不显示在画布上，因此只更新位置并继续留在总览。

按需时间编辑也必须连续：点击“添加具体时间”后聚焦刚出现的开始时间输入；如果点击“移到随手页”让整块时间编辑器消失，则焦点回到仍存在的日期字段。修改开始时间时，原结束时间只在不再晚于新开始时间时清除；仍然合法的结束时间保持不变，避免用户重复填写。它们只修复触发控件消失后的落点和无效区间，不增加确认步骤，也不在 Inspector 初次打开时抢走标题焦点。

撤销日期修改也具有对称的空间结果：如果当前 Inspector 仍指向这张 Card，撤销后读取恢复 Workspace 中的 placement，页面跟随到恢复后的日期页或随手页，详情保持打开。如果恢复状态中已不存在该 Card，关闭 Inspector，不能展示幽灵详情。其他普通撤销不为了“看起来有动作”而擅自翻页。

这里需要区分“浏览页面”和“移动 Card”：前一天、后一天、今天、随手页与日期选择器都属于手动浏览，会先提交有效 draft，再关闭旧 Card Inspector；在 Inspector 中修改当前 Card 的日期则属于移动 Card，页面跟随 Card 且详情保持打开。搜索或总览定位目标 Card 时，切页后打开的是目标 Card 的详情，不能残留旧 Card 上下文。

标题与备注先在 Inspector 内形成 draft，Card 双击后的就地标题也使用同样的 draft 边界；失焦或明确确认时一次提交，卸载与窗口退出前刷新最新合法内容。就地标题按 Enter 保存、按 Escape 取消时，输入框消失后回到重新出现的同一张 Card；鼠标或 Tab 移到其他控件造成的 blur 只保存合法文字，不覆盖用户的新焦点。日期、时段和优先级可以立即提交。一次连续文字编辑只产生一次持久化，不让每个字符都进入保存队列。备注 placeholder 固定为 `补充备注...`，不再写“也可以保持空白”这类解释。关闭 Inspector 时，合法 draft 先提交，再判断原入口是否仍连接且处于可见视图：可见才返回原 Card 或列表行；若总览已经隐藏，则优先返回当前画布中同一张 Card，仍不存在时回到底部捕获栏。鼠标点击或触控轻点画布空白且未越过平移阈值时，执行同一套提交与关闭协议：Card Inspector、Area Inspector 或就地标题收起后，焦点回到原 Card 或 Area，而不是落到页面根节点；若用户点击的是另一个可聚焦控件，则保留新控件的焦点。

选择 Area、新建 Area、完成 Card 和开始拖动都属于明确的提交边界：先提交当前合法 Card / 就地标题 draft，再读取最新 Workspace 执行动作。这样文字编辑不需要用户先点一下空白处才能安全地继续操作，也不会因为旧闭包只保留了状态或坐标而丢失标题。

## 总览与搜索

### 总览

总览是清爽索引，不是管理后台：

- 单列内容区。
- Header 只显示“总览”，不使用 kicker 或介绍段落。
- “未完成 N / 已完成 N”内部切换，数量来自同一份 Card 数据。
- 未完成内容分为“日期页 / 随手页”。
- 有日期 Card 按日期与时段派生排序。
- 无日期 Card 按创建时间派生排序。
- 不保存列表顺序，不提供拖动排序。
- 首批最多呈现 64 行，随后每次增加 64 行；用户接近列表末尾时自动续载，同时保留一个可点击、可聚焦的“再显示 N 张”入口。
- 日期页与随手页都存在时，首批按完整数量比例分配并保证两组至少各出现一行，避免较小的一组在长列表中看似消失。
- 未完成 / 已完成数量读取完整数据，不随当前已呈现批次变化；切换状态或重新进入总览时回到首批，保持进入速度和位置预期稳定。
- 空状态只保留“没有未完成的卡片”或“还没有完成的卡片”一行，不再解释用户接下来应该做什么。

“未完成 / 已完成”不是在同一个详情背后更换背景。用户切换状态时，先提交当前合法 Card draft 并关闭旧 Inspector，再显示目标索引；状态按钮保留刚获得的焦点。这样列表、详情与键盘现场始终指向同一个总览状态，不增加确认步骤。

未完成行只提供完成、打开与定位，已完成行提供恢复与打开。定位先切到 Card 的 pageKey，再移动视口并短暂强调 Card。

可打开详情的标题要像文字入口，而不是伪装成静态标签：悬停时仅让标题颜色在 140ms 内显现，按下时整个标题入口在 90ms 内缩至 0.99。总览行本身不增加背景、边框、阴影或抬升，避免把清爽索引重新做成一列 Card。

完成或恢复都会让当前筛选中的行消失。产品保持用户选择的“未完成 / 已完成”状态，不为了让焦点有落点而自动切换列表或画布；如果焦点仍停在即将消失的完成 / 恢复按钮上，行移除后立即回到底部捕获栏。总览行没有 Card 离场动画，不等待画布完成的 260ms。如果用户已经主动聚焦其他控件，则保留用户的新焦点。

定位必须改变用户实际看到的画布，而不只是改变下一次保存或重载才会读取的 viewport。可见 transform、当前页会话 viewport、缩放反馈与 Workspace viewport 使用同一个计算结果；用户此前无论怎样平移，定位后目标 Card 都进入视野。

总览不是“把画布重新整理成列表”的任务。它是一个索引投影，不承担独立的编辑模型：列表顺序由日期、时段和创建时间派生，用户不需要在两个视图之间维护两套位置或排序；完成、恢复和打开详情仍然作用于同一张 Card。

### 一级视图与大数据量边界

“画布 / 总览”是同一份 Workspace 的两种一级投影；对话面板只在画布上按需挂载。画布与总览之间切换时一次只保留目标一级视图的完整界面树，避免 1,000 张 Card 时不可见总览继续参与提交，也避免隐藏控件进入焦点、读屏或测量现场。对话打开时不卸载画布背景，只增加一个独立、可访问的面板；收起后移除其可交互 DOM。切换之前仍先提交合法 draft、关闭不属于目标视图的 Inspector，并把焦点交给真实可见的目标界面；对话的草稿、历史、候选和待确认状态不属于 Workspace，继续保留在当前应用会话中。

总览的渐进呈现只控制 DOM 数量，不改变产品语义：排序、分组、筛选、完成状态和顶部总数始终基于全部 Card。`IntersectionObserver` 在末尾入口进入滚动预取范围时自动加载下一批；同一个入口也是普通按钮，因此键盘用户、辅助技术和没有观察器能力的环境都能继续到达全部内容。这里不使用无限滚动隐藏“还有多少”，也不把未渲染 Card 误报为空。

固定性能数据集包含 1,000 张 Card，覆盖多个日期页、随手页、未完成、已完成与已删除状态。发布预算使用 React Profiler 的累计提交时长：捕获 `<40ms`、翻页 `<40ms`、Card 拖放 `<40ms`、搜索 `<30ms`、总览首屏 `<80ms`。这些数字约束渲染回归，不替代真实 Tauri 窗口中的感知流畅度、焦点、动效和拖动验收；命令固定为 `pnpm test:performance`。

### 搜索

- macOS 显示并使用 `⌘ K`；Windows 与 Linux 显示 `Ctrl K`，两类修饰键都可以打开。
- 搜索标题和备注。
- 结果显示足够辨认同名 Card 的日期、时段和完成状态。
- 未完成 Card 回到所属页面。
- 已完成 Card 进入总览的已完成状态。
- 进入已完成结果前先结束旧 Card / Area Inspector 与 Card 就地编辑，不能让无关详情漂在总览之上。
- 搜索不会修改 Card 页面或坐标。
- 上下键移动结果时，当前项始终保持在滚动视野内；关闭后焦点回到打开搜索的控件或捕获入口。
- 搜索输入通过 `aria-controls` 关联结果列表，并以 `aria-activedescendant` 指向当前高亮项；视觉高亮、Enter 打开的 Card 与辅助技术读到的活动结果保持一致。
- 搜索已经打开时，重复 `⌘ K` / `Ctrl K` 不重置查询、结果或焦点；快捷键只负责进入搜索，不兼作“清空搜索”。
- 删除确认或备份导入确认打开时，搜索快捷键不生效；破坏性或数据替换决策不能被一个全局入口盖住。
- 从捕获输入进入搜索时，快速候选先隐藏；关闭搜索回到仍含有效片段的捕获输入后，候选按当前文字恢复。

## 浮层与焦点

日期选择器、搜索、确认框、Inspector 和 Agent 面板都是画布 / 总览之上的短暂层级；Agent 面板虽是一等操作能力，但不是一级视图。它的候选、确认和回执仍是面板内部的临时层级，不应让用户失去操作现场。

- Escape 关闭当前最上层。
- 非破坏性浮层允许点击外部关闭；确认删除必须显式取消或确认。
- 模态对话框打开时 Tab 留在对话框内。
- Escape 或点击普通空白关闭后，焦点返回触发控件；若触发 Card 已完成、恢复、删除或进入隐藏视图，则返回当前可见的同一 Card，仍不存在时回捕获入口。
- 点击另一个按钮、输入框、链接或其他可聚焦对象关闭浮层时，保留 pointer 新目标获得的焦点，不执行旧入口恢复。
- 搜索和备份触发器使用 `aria-expanded` 表达真实状态；备份触发器的名称表达下一步是打开还是关闭菜单。
- 普通界面更新不能取消正在进行的拖动；若用户试图打开冲突浮层，应先结束或取消当前手势，再切换层级。

不同临时层和一级视图的焦点规则保持固定：

| 层级 | 进入后 | 键盘 | 离开后 |
| --- | --- | --- | --- |
| 搜索 | 聚焦搜索输入；没有查询时不伪造结果选择 | 上下键浏览，Enter 打开，Tab 留在对话框，Escape 关闭 | Escape 或空白关闭回实际入口；外部可聚焦动作关闭时保留新焦点；入口不存在时回捕获栏 |
| 对话 Agent | 打开覆盖面板时聚焦独立输入；存在当前 Card 时显示可感知的上下文描述 | Enter 发送；Tab 可以到达回执、候选和确认；Escape 先结束最内层候选或确认，再收起面板 | 收起或切换总览时保留对话草稿、历史和待确认状态；焦点回到真实可见的画布工具入口或总览入口 |
| 日期选择器 | 聚焦正在查看的日期或最近的可操作日期 | Tab 留在选择器，Escape 关闭 | Escape、空白关闭或选择内部日期后回唯一日期按钮；点击仍存在的随手页、前一天、后一天、今天等外部动作时保留新焦点 |
| 删除确认 | 默认聚焦“取消”，避免把破坏动作变成默认动作 | Tab 留在确认框，Escape 等同取消 | 取消后回删除按钮；确认删除后回捕获栏 |
| 备份导入确认 | 默认聚焦“取消”；文案明确当前画布会被替换、导入后仍可撤销 | Tab 留在确认框，Escape 等同取消 | 无论取消或完成都回到备份入口 |
| Card Inspector | 聚焦首个可编辑字段，但不自动全选覆盖内容 | Escape 或未形成平移的画布空白点击先提交最新合法 draft 再关闭；手动翻页也先提交再关闭 | 原入口可见才返回；否则回当前画布同一 Card，再回捕获栏。手动翻页后不恢复旧 Card 焦点 |
| Area Inspector | 仅在新建或明确打开后聚焦名称；新建时全选默认名，已有名称不自动全选；键盘路过把手不打开 | Enter 提交；Escape 放弃当前未提交改名并关闭；画布空白点击先提交合法名称再关闭 | 关闭回到 Area 移动把手；删除回到捕获栏 |
| 备份菜单 | 聚焦第一个菜单项 | 上下键循环，Escape 关闭；选择导入后先收起菜单再打开系统文件选择器 | Escape 或取消文件选择回菜单按钮；点击外部时保留新点击目标 |

破坏性入口与确认层遵守同一套触感，但不能靠改色制造刺激：删除入口在 140ms 内显色，悬停轻抬 1px，按下在 90ms 内缩至 0.97；确认层按钮悬停轻抬 1px，并把阴影收紧到 2px，按下沿用既有轻压。主操作与危险操作的背景色保持不变，文字对比继续达到 WCAG AA。

本地内容读取失败不建立新的管理流程，只提供原位重试。用户触发“重新打开本地内容”后，读取成功就回到底部捕获输入，可以立刻继续记录；若仍然失败，焦点回到重新出现的重试按钮，允许再次操作。两种结果都不能把焦点留在 `body`，也不能以空 Workspace 覆盖原数据。

一级视图切换与页面离开虽然不是模态关闭按钮，也必须复用同一套“提交 draft → 结束旧层 → 进入新现场”的边界。不要依赖 input blur、pointer 事件冒泡或 React 卸载顺序偶然帮忙保存。

任意时刻只允许一个模态焦点域。普通临时层之间切换时，先结束旧层再进入新层；删除确认与备份导入确认具有更高优先级，搜索等全局入口必须等待确认结束，不能替换或叠在确认框之上。关闭动作不能把焦点送进已隐藏、已完成、已恢复或已删除而离开当前视图的 Card。

快速候选不是模态层，但也不能在搜索背后继续作为活动控件。搜索打开前把它标记为暂时收起；搜索关闭并把焦点还给捕获输入后，若 `#` / `!` 片段仍然有效，则由现有输入重新推导候选。这里不保存第二份候选快照，也不清空用户文字。

对话与普通捕获各自只有一个活动输入现场。打开对话时暂时收起普通捕获的快速候选并保留其 draft；收起面板或回到画布后再从原文字重新推导候选。对话中的 Card 候选、批量预览与确认属于面板内部层级，Escape 每次只结束最内层。破坏性确认打开后，搜索、日期选择器和新的对话请求都等待确认结束；切换到总览不会清除对话会话。

不带 Shift 的 `⌘ Z` / `Ctrl Z` 也遵守层级边界。输入框、文本域和选择控件继续由控件自身处理撤销；搜索、日期选择器、备份菜单或确认框存在且焦点位于非文本控件时，应用阻止默认动作但不消费 Workspace 历史。citroam 当前没有 redo，因此 `⌘ Shift Z` / `Ctrl Shift Z` 不执行任何 Workspace 操作，也不能退化成又一次 undo。产品不为这两种情况增加提示或按钮：临时层已经说明用户正在做什么，而尚未提供的 redo 保持安静；Escape 结束当前层后，Workspace 撤销立即恢复。

## 本地备份

本地优先必须同时提供离开设备内部存储的安全出口。备份归入标题栏的低频菜单，不成为独立主按钮或新工作流：

- 入口使用硬盘 / 存储语义图标，不复用 citroam 品牌图标；可访问名称明确包含“本地备份”，悬停提示为“本地备份”。
- 导出完整 Workspace JSON；导出完成并关闭菜单后，焦点回到本地备份入口。
- 导入前校验 schema 和全部引用关系。
- 选择导入后先关闭应用菜单，再打开系统文件选择器；取消文件选择后焦点回到备份入口。
- 校验通过后显示应用内确认层：标题为 `导入这份备份？`，说明为 `当前画布会被替换。导入后仍可以撤销。`；默认安全动作是取消。
- 确认前不修改 Workspace；确认后才替换，并把替换作为一次可撤销动作。
- 确认层支持 Escape 取消与 Tab 焦点陷阱；关闭后焦点回到备份入口。
- 校验或写入失败时保留当前内容并说明原因；若失败发生在确认层出现之前，焦点回到本地备份入口。

备份不是云同步，不建设账号、版本历史或多人协作。

## Juicy Utility 视觉语言

设计目标是“80% 清晰工具，20% 饮料品牌式轻松”。现代主义提供秩序，包豪斯提供形状诚实，蒙德里安提供受控色块，屈米提供空间事件；它们不是可见主题皮肤。

### 现代主义原则

- 功能决定层级：页面、Card、Area 的形态直接对应职责。
- 网格用于导航和总览，不强迫画布内容对齐。
- 大面积留白与少量高饱和强调色。
- 字体层级取代装饰性边框堆叠。

### 品牌 Token

| Token | 浅色 | 用途 |
| --- | --- | --- |
| Canvas | `#F4F6EA` | 整体背景 |
| Surface | `#FFFDF7` | Card 与浮层 |
| Ink | `#24271F` | 主文字 |
| Citrus | `#F06A3B` | 唯一强强调色 |
| Lemon Foam | `#FFE8A6` | 完成气泡、当前状态 |
| Lime Fizz | `#DDEBB5` | Area、随手页 |
| Soda Mint | `#D8ECE7` | 日期页时段背景与时间语义 |

- 不使用渐变。
- 不使用纯黑、纯白、霓虹光晕与彩色重阴影。
- 深色主题保持同一色彩关系，不变成另一套品牌。
- 装饰几何必须低对比、静止且不影响命中。

### 形状

- Card：18 / 18 / 18 / 10px。
- 日期区域：22 / 22 / 22 / 14px。
- 捕获栏：20px。
- 控件：10–13px。

不对称圆角像饮料标签与气泡边缘，但不能让应用变成儿童玩具。

## 动效系统

| 事件 | 时长 | 动作 |
| --- | --- | --- |
| Card 创建 | 220ms | 淡入、上移、0.94 → 1.03 → 1 |
| Card 拖起 | 即时 | 阴影、1.025 scale、极轻旋转 |
| Card 放下 | 200ms | 快速减速回到静止 |
| 画布 Card 完成 | 260ms | 先保存完成状态，再以轻微放大、淡出离开当前画布；动画结束后才恢复原控件的焦点 |
| 总览行完成 / 恢复 | 即时 | 行直接离开当前筛选并立即恢复焦点，不借用画布 Card 的动画延迟 |
| 反馈轨道子项 | 180ms | 提示、撤销和保存失败各自淡入上移；位置由共享轨道一次布局，不做互相避让动画 |

| 现有按钮 hover / pressed | 90–140ms | 捕获提交、快速 token、撤销与恢复动作轻抬或轻压，时段、浮层关闭和临时选择项显色并轻压，前日书签轻抬并收紧阴影；Area 把手、删除 / 确认动作补齐显色、轻抬或轻压，总览标题只做文字显色与极轻按压；入场位移或缩放不覆盖后续交互 transform，不新增常驻装饰或总览行卡片化 |
| 日期翻页 | 180ms | 22px 水平位移 + opacity |
| 日期选择器 | 180ms | 上移 7px + opacity |
| 前日书签 | 180ms | 左侧轻移 + opacity |
| 快速菜单 | 180ms | 上移 + opacity |
| Agent 面板 | 220ms | 在当前画布右下角淡入并轻微上移 8px；不遮罩、不缩放、不抢回用户焦点 |
| 对话消息 | 120ms | 用户文字与操作回执轻微上移并落定；不制造逐字打字动画 |
| Agent 批量预览 | 150ms | 当前页可见目标使用半透明虚线轮廓淡入；确认、取消或失败后淡出，不写 Workspace，且轮廓 `pointer-events: none`、`aria-hidden="true"`。 |
| Inspector | 260ms | 从右侧进入 |
| 搜索 / 确认 | 220ms | scale + opacity |
| 定位 Card | 260–300ms | 视口移动 + 一次强调环 |

动效原则：

- 拖动期间不补间位置。
- 动画主要使用 transform 与 opacity。
- 入场动画需要和后续 hover / pressed 共存时，使用独立的 `translate` / `scale` 属性，不能长期占用交互所需的 `transform`。
- 不使用常驻循环；真实加载可以使用克制的状态变化，但 Agent 不使用三个跳点或人为延迟表演思考。
- 快速连续操作后不能留下错误 transform、opacity 或 pointer state。
- `prefers-reduced-motion: reduce` 下功能与焦点行为完全相同。
- reduced-motion 覆盖块必须位于所有组件动画规则之后，避免后续页面、Agent 面板或反馈样式重新启用动画；该顺序是实现约束，不改变正常模式的动效时长。

## 交互架构

画布操作统一为四阶段：

```text
begin → move → commit
          ↘ cancel
```

- `begin`：保存 pointerId、对象身份和原始几何。
- `move`：直接更新临时 DOM，不写 Workspace。
- `commit`：释放时只提交一次 reducer、Undo 和最终保存。
- `cancel`：Escape、pointercancel、窗口失焦或卸载时还原临时样式。

同一时刻只能有一个活动会话。普通 React render、保存状态变化、日期文案刷新或选中变化不能取消正在进行的手势。

点击与拖动共用同一表面时，必须先经过统一位移阈值再决定语义。当前阈值为横纵位移绝对值之和超过 4 CSS px；阈值以内视为轻点，越过后视为拖动。Card、Area 空白平移、Area 移动、Area 缩放、Space + 左键平移与中键平移都遵守这条阈值，阈值以内不得改几何或视口、保存 Workspace 或增加 Undo。Area 空白的 pointerdown 可以开始画布平移，但手势一旦越过阈值，本次 pointerup 后的合成 click 必须被消费；没有形成拖动的明确轻点直接打开 Area Inspector，不依赖浏览器补发 click。Card、Area 移动、缩放或任一鼠标平移越过阈值后也消费同一序列的 click，即使指针最后回到原几何或原视口；没有净变化时仍不保存。抑制只作用于刚结束的同一次手势，不能让后续正常点击失效，也不能拦截 Card、Area 把手或表单控件自己的后续事件。普通左键在页面空白按下且没有形成平移时属于关闭现场：先提交合法 draft，再关闭当前 Inspector 或就地编辑，不修改视口。

鼠标 Card 在阈值以内保持普通 click 语义：pointerdown 不提前 `preventDefault`，也不抢 pointer capture；只有移动意图越过 4px 后，才启用 pointer capture 并抑制原生选择或滚动。这样“点击打开”和“拖动移动”共享同一表面，却不会因为拖动仲裁把 Inspector 的 click 一起吞掉。触控 Card 仍在 pointerdown 阶段保持既有 capture 与 tap / drag / pinch 仲裁。

直接操作的 cursor 同样服从阈值。pointerdown 到阈值以内仍保留 pointer / grab，只有 Card 或 Area 移动意图成立后，指针真正停留的 Card 标题表面或 Area 移动把手才显示 grabbing；commit 与 cancel 都立即恢复。缩放把手继续使用 nwse-resize，不因 Area 的其他状态被误改。

Space + 左键平移中的 Space 是临时修饰状态，不是可跨窗口保留的模式。它拥有高于 Card 拖动和 Area 移动 / 缩放的优先级，因此可以从页面空白、Card、Area 空白或 Area 把手开始；中键从同样的表面开始也只表达平移。两者都在越过 4px 后才更新临时视口，对象始终保持原位；一旦形成平移，释放后的合成 click 被消费。窗口失焦时既取消活动空间手势，也释放 Space 状态；返回应用后普通左键仍是普通左键，只有重新按住 Space 才进入平移。

交互优先级只有一套：

| 输入 | 起点 | 结果 |
| --- | --- | --- |
| Space + 左键 | 页面空白、Card、Area 空白、Area 把手 | 只平移画布。 |
| 中键 | 页面空白、Card、Area 空白、Area 把手 | 只平移画布。 |
| 普通左键拖动 | Card | 只移动 Card。 |
| 普通左键拖动 | Area 移动 / 缩放把手 | 只移动或缩放 Area。 |
| 单指越过阈值 | 页面空白或 Area 空白 | 只平移画布。 |
| 单指未越过阈值 | Area 空白 | 打开 Area Inspector。 |
| 单指未越过阈值 | 页面空白 | 提交合法草稿并收起当前详情或就地编辑。 |
| 普通左键未越过阈值 | 页面空白 | 提交合法草稿并收起当前详情或编辑态。 |

每次指针序列只能得到一个结果。完成平移、Card 拖动或 Area 变形后，释放事件不能再触发详情打开；抑制在该序列结束后立即失效。

日期页几何使用单一事实来源：

- 日期画布边界。
- Card 尺寸。
- 四个时段的 top / bottom。
- 新 Card / Inspector 的 Card 收边建议。
- Card 中心到时段的映射。
- 新 Card 建议位置。

视觉时段与拖动写入不能使用两套边界。

每个日期页和随手页在当前会话中拥有独立视口。世界 transform、缩放百分比以及放大/缩小按钮的 disabled 状态必须读取同一个当前页视口；返回 180% 的页面时，控制栏不能仍显示另一个页面的 100%。任何需要在“眼前”创建、跨页移动或定位对象的命令也必须读取目标页这份 visible viewport，不能绕回 Workspace 的旧 viewport。日期页自动放置优先改变新 Card 的候选槽，不移动已有 Card；只有目标时段完全离开视野时才最小幅度调整观察位置。

### 缩放锚点

缩放改变的是观察比例，不应该改变用户正在观察的对象。三种入口使用与动作最接近的锚点：

| 入口 | 锚点 | 体验结果 |
| --- | --- | --- |
| 加减按钮 | 可见舞台中心 | 当前视野中心的内容保持在中心。 |
| `⌘ / Ctrl + 滚轮` | 指针在舞台内的位置 | 指针指着的 Card 或画布位置不从指针下滑走。 |
| 双指缩放 | 两指中点 | 双指夹住的画布位置保持稳定。 |

锚点换算必须同时更新 `x`、`y` 与 `zoom`，三者作为同一个视口目标进入可见 transform 和 Workspace。比例限制为 `0.5–1.8`；到达边界后继续缩放没有视觉变化，也不保存或制造 Undo。加减按钮、修饰键滚轮与双指行为均已有回归覆盖。

## 响应式与可访问性

### 窄窗口

- Tauri 桌面窗口不小于 760×560；这个尺寸是产品布局的一等验收状态，不只是 CSS 断点。
- 页面导航压缩但保留随手、前后日期、日期选择，以及离开今天时按需出现的“今天”；只隐藏装饰分隔线。
- 捕获栏保持全宽可用。
- Agent 面板保持在安全区域内，两侧至少留 16px；输入、入口、回执和确认始终可达，消息区独立滚动不能带动背后画布。
- Inspector 变为不超过窗口宽度的右侧层。
- 总览元数据换行，不横向滚动。
- 标题栏可隐藏品牌文字与保存成功反馈，搜索可收为图标，捕获栏可隐藏快速语法提示；这些都不能移除相应功能。
- 保存失败与重试属于关键状态，不能与“已存到本机”成功文案一起被静默隐藏；它们与撤销、异页提示共用捕获栏上方的反馈轨道。三项同时出现时仍需完整可读、可操作，不互相覆盖、不被窗口裁掉，也不遮住页面导航或捕获栏。
- 主页面不得依赖横向滚动到达总览、搜索、日期导航、捕获或缩放。
- 桌面 Tauri 是当前发布基线。窄窗口适配只代表布局可用，不代表触控手势已经完成。
- 移动端也不引入额外的日期卡片容器。

### 触控发布门槛

只有以下交互全部成立时，citroam 才宣称触控可用：

- 单指拖空白平移画布。
- 单指拖 Card 移动 Card。
- 双指缩放画布。
- 捕获栏、日期导航和 Inspector 不与系统手势冲突。
- 对话在触控版使用单列安全浮层；消息滚动、一级导航和对话输入互不串台，画布仍是可见且唯一的操作现场。
- `touch-action: none` 不产生既不能滚动也不能平移的死区。

双指缩放遵循一条连续手势，而不是两个互相竞争的 pointer 会话：

1. 第一指落在空白画布时可以开始平移。
2. 第二指落下后，当前会话升级为双指缩放，以两指中点对应的世界坐标为锚点。
3. 移动时只更新临时 transform，缩放限制为 `0.5–1.8`，不逐帧保存。
4. 任意一指抬起时结束本次双指手势并一次提交最终视口；剩余触点抬起前不重新开始另一个手势，避免跳变。
5. `pointercancel`、窗口失焦或组件卸载恢复手势前 transform，不遗留 pointer capture 或半完成状态。

不为移动端复制一个传统列表 Todo；总览已经承担规整浏览，画布仍保持同一底层模型。

### 可访问性

- 所有图标按钮具有 aria-label。
- 日期画布、随手页、总览和菜单使用明确 landmark / role；日期页面入口是命名 navigation，画布操作区是命名 region，紧凑画布导航是命名 group。
- 日期与时段不只依赖颜色。
- 时段名称与拖动后的时间结果可被辅助技术理解，不能因为背景层 `aria-hidden` 而完全丢失语义。
- 日期复合按钮保留稳定动作名称，并把当前日期关联为可访问描述；读屏用户不打开选择器也知道正在看哪一天。
- 删除与备份导入确认把已有后果文案关联到对话框；默认焦点仍在取消，不额外重复可见说明。
- 可交互控件至少 32px 高。
- 键盘焦点统一使用 `--focus`，规则在组件级 `outline: 0` 之后生效，在明暗主题的 Canvas 与 Surface 上至少达到 3:1。
- 捕获、搜索、对话、打开、编辑、完成、恢复、关闭浮层和撤销可以只用键盘完成。
- 正文、次级文字、危险操作达到 WCAG AA。
- 深色主题与减少动态效果为一等状态。
- “正在打开 / 正在保存 / 已存到本机 / 尚未保存”使用 polite、atomic live region，让状态可感知但不打断当前输入；成功文案视觉退场不移除其播报语义，错误不会自动消失。
- Agent 流式回应、当前上下文、候选、批量数量和最终回执具有稳定语义；只有新增内容进入 polite live region，不让每个流式片段重复朗读整段历史。

## 文案语气

文案轻，但不装可爱；温和，但不含糊。能用标签、数量和状态说明的事情，不再写成气氛句。

使用：

- `放进今天...`
- `放进随手页...`
- `补充备注...`
- “看全本页”
- “前一天还留着 3 张。”
- “已放到明天。”
- “没有未完成的卡片。”
- “好，放到明天下午了。”
- “会移动 6 张 Card。”
- “现在没有处理成功，画布没有变化。”

避免：

- “慢慢醒来”
- “顺着状态往前”
- “给一天轻轻收尾”
- “全都在这”
- “画布负责随性，这里负责看全”
- “先放下来，不急着分类”
- “补一点上下文，也可以保持空白”

## 设计完成标准

citroam 的产品体验只有在以下状态同时成立时才算完成：

1. 用户不需要创建日期，也永远不需要清理日期对象。
2. 今天、任意日期与随手页都能一步或两步到达。
3. Card 仍然自由，不被日期页重新变成列表。
4. 时间语义清楚，但不演化为日程管理器。
5. 没做完的昨天可以找回，但不会自动压到今天。
6. 总览完整，画布自由，两者不产生双重维护。
7. 拖出日期边界的 Card 仍能通过“看全本页”看见，定位结果不会被重叠 Card 完全遮挡。
8. 用户可以预见 Card 放下后的时段与吸附位置；末尾快速 marker 可以直接紧接中文标题，候选与 styled token 正常出现，无需额外空格也能提交。
9. 视觉轻松、有品牌感，直接操作仍然清晰可靠。
10. Agent 是画布上的原生操作层；入口始终可见，打开后可用一句话维护 Card，普通捕获与直接操作不经过 Agent；生产请求走真实 Harness，Harness 不可用时该次请求 no-op，不覆盖本地手势现场。
11. 日期页 Card、总览与搜索按各自上下文显示时间，不重复日期信息。
12. 时段、空随手页和总览不依赖解释型品牌文案，当前页缩放反馈始终准确。
13. 日期选择只有一个复合按钮；随手页捕获、备注和备份入口都使用直接文案与准确图标，不重复入口、不复用品牌图形表达工具语义。
14. 常驻纯图标动作可通过悬停和辅助技术理解；画布与总览的完成圆圈统一提示“完成”。捕获提交、快速 token、时段选择、浮层关闭、前日书签、撤销、临时选择项、错误恢复、Area 移动 / 缩放把手、删除 / 确认动作与总览标题入口具有一致且真实生效的 hover / pressed 反馈；Area 把手显现和按压不突跳，Card / Area 移动成立后 cursor 真实进入 grabbing，危险动作不牺牲对比度，总览标题不引入行背景、边框或 Card 装饰；全局键盘焦点统一使用达到 3:1 且不被组件重置覆盖的 `--focus`，日期控件与确认框暴露已有上下文；入场动效不能覆盖交互位移或缩放，已经移除的界面不保留死样式；关键次级文字不靠极小字号制造“精致感”。
15. 760×560 最小桌面窗口仍保留创建、翻页、搜索、编辑、完成和错误恢复的完整路径。
16. 完整快速 token 一次 Enter 创建；有无 marker 前分隔空格的候选、解析与标题结果一致，优先级文字前后一致；从总览改时间后的去向符合 Card 是否在画布可见，就地标题不会因直接退出而丢失。
17. 手动翻页结束旧页面详情并先保存有效草稿；Card 自己换日期时详情随 Card 保持，搜索与总览只携带明确目标的上下文。
18. 任意画布 / 总览切换、离开随手页和搜索进入已完成结果会提交有效草稿并结束无关的 Card / Area / 就地编辑现场；打开或收起对话面板不改变一级视图，对话会话状态按约定保留。
19. 从总览或搜索定位 Card 会真实更新屏幕可见视口；撤销 Inspector Card 的日期变更时，Card、页面与详情恢复为同一个现场。
20. 已完成 Card 的日期修改与撤销不会改变隐藏画布现场；选择 Area、完成、Card 拖动与 Area 变形不会覆盖未失焦的合法草稿；备份导入在应用内明确确认，确认和取消都回到入口；Area 操作在键盘焦点进入时可见。
21. 最后一次撤销、Card 完成、从已完成总览恢复 Card、移除快速 token、展开具体时间、移到随手页、Area 删除，以及 Card 就地标题用 Enter 保存或 Escape 取消，都不会把焦点留在页面根节点；这些动作不通过自动切换视图掩盖焦点问题。就地标题回到同一张 Card；Area 新建直接命名，Enter 保存名称后仍留在输入，关闭回到原 Area，键盘路过操作把手不会弹出详情；保存状态和画布结构可被辅助技术理解。
22. 外部动作关闭搜索、日期选择器或备份菜单时保留新焦点；日期选择器打开时点击仍存在的页面导航也遵守这一规则，选择器内部会消失的日期选项则回到日期按钮。Inspector 不返回隐藏视图；备份导出和无效导入回到备份入口；总览行无动画时立即恢复焦点，画布 Card 仍保留离场动画与不抢焦点规则。
23. 快速语法候选离开捕获栏时收起、回到仍含有效片段的输入时恢复；搜索与备份入口准确表达展开状态；导入菜单在系统文件选择器出现前收起，取消选择后回到备份入口。
24. 确认框拥有高于全局搜索的操作优先级；搜索快捷键重复触发不清空现有查询；搜索与快速候选之间的切换只有一个活动焦点域，并能无损回到原输入现场。
25. Workspace 撤销不穿透搜索、日期选择器、备份菜单或确认框；输入控件保留原生撤销，离开临时层后画布撤销继续可用。
26. 快速候选展开且 Card Inspector 打开时，第一次 Escape 只收起候选并保留输入与 Inspector；`⌘ Shift Z` / `Ctrl Shift Z` 在没有 redo 时保持安静，不消费 undo 历史。
27. 总览状态切换提交并关闭旧 Card Inspector，且保留状态按钮焦点；中文输入法 composition 期间 Enter 等按键保持原生；窗口失焦释放 Space + 左键平移状态。
28. 页面导航以实际 `pageKey` 变化为离场边界；重复选择当前日期或当前随手页保持 Card / Area Inspector、未离场草稿与当前视口，不制造保存、撤销历史或换页动画。
29. 异页捕获提示、撤销与保存失败恢复只使用一条反馈轨道，可同时出现但不重叠或遮住日期导航；保存重试按钮消失后焦点回到捕获输入。
30. 760px 最小桌面窗口仍保留按需出现的“今天”返回动作，只收起日期导航中的装饰分隔线。
31. Area 空白的轻点不依赖合成 click 即可打开详情；触控平移、移动 Area 或缩放 Area 在越过阈值后只完成各自手势，释放时不会继续合成点击并误开 Inspector。
32. Space + 左键从页面空白、Card、Area 空白或 Area 把手开始都只平移画布，不移动对象；释放后不打开 Card 或 Area 详情，下一次普通点击仍然有效，窗口失焦后也不会遗留 Space 模式。
33. 日期导航中的星期只出现一次；随手页新建 Card、新建 Area 与从日期页移入的 Card 都使用目标页当前 visible viewport 与 zoom 落在眼前，可见槽位填满后回绕叠放，不受其他页面或旧持久视口影响。
34. 空随手页执行“看全本页”保持眼前现场，不跳到其他页面遗留视口，也不制造保存或撤销。
35. Area 移动与缩放在 4px 内抖动时保持原几何；加减按钮围绕视野中心、修饰键滚轮围绕指针、双指围绕中点缩放，用户正在看的位置不会因缩放入口不同而漂移。
36. 空随手页的“看全本页”明确禁用；已经满足的视口与时段命令保持幂等，不闪保存状态、不改变层级、不制造 Undo。
37. Card 拖动越过阈值后即使回到原点也不会打开详情；定位另一张 Card 前提交旧现场，并从最新 Workspace 计算结果。
38. 修改具体开始时间时保留仍晚于它的结束时间；仅在原结束时间不再合法时清除，时间编辑不会无声丢失仍然有效的信息。
39. 普通左键点击画布空白会提交并收起当前 Card / Area Inspector 或就地标题，焦点回到原对象；新 Area 的默认名称完整选中，可直接输入替换；Space + 左键与中键在 4px 内抖动不移动视口、不保存，真正平移后不误开详情。
40. 远日期捕获栏明确写出月日或年份；日期页和随手页的新 Card 先复用开放槽位，全部占用后才回绕叠放；新 Area 优先复用未占用偏移，不会与仍存在的 Area 完全同坐标。
41. 触控轻点画布空白与鼠标点击使用同一收口协议，Card / Area Inspector 和 Card 就地标题都会先提交再关闭并回到原对象；触控拖动仍只平移，不会因为结束手势顺便关闭现场。
42. 日期选择器持续标记正在查看的日期，键盘焦点移开后当前态仍可见；Area 默认名只在新建后的首次聚焦被全选，已有 Area 不因名称相同而被当作占位内容。
43. 在前台跨过本地午夜，或应用重新获得焦点 / 可见性时，相对日期和“今天”入口自动刷新；当前页面、Card、视口、Inspector 与草稿保持不变，不保存，也不产生 Undo。
44. 随手页打开日期选择器时可以默认聚焦最近浏览日期，但任何日期都不显示 `aria-current="date"`；只有真实日期页拥有日期当前态。
45. 本地内容读取重试成功后焦点回到捕获输入；若仍然失败，焦点回到重新出现的重试按钮，不落到页面根节点，也不覆盖原内容。
46. 日期页横向平移或窗口收窄后，新建 Card 优先复用目标时段中完整可见的安全槽；候选全部占用后可以回绕叠放，但最新 Card 仍留在眼前。
47. 日期页当前视野完全离开目标时段时，新建或跨日移动未完成 Card 只触发足以露出目标的最小视口移动；创建与视口变化共用一次 Undo，跨日移动继续保持 Card、目标页和 Inspector 同时可见。
48. 日期页面入口具有命名 navigation landmark；Web favicon 直接复用原生 citroam SVG 图标源，不产生另一套品牌标记。
49. 快速语法捕获到非当前日期页时，当前页与输入现场保持不动；目标页即使曾被平移，用户之后第一次翻入仍能看到最新捕获的 Card，且系统不重排其他 Card。
50. 在总览捕获到当前日期页时继续留在总览；用户主动返回曾经平移过的画布后，新 Card 仍在可见安全范围内。
51. 捕获主链路只有输入与 Enter；创建不会插入表单、推荐、解释或等待外部服务的步骤。
52. 核心操作无需账号和网络；用户可以导出本地内容，普通修改可撤销，破坏性操作有明确后果与备份恢复路径。
53. 未完成事项不会被包装成评分、连胜、欠债或系统对用户的判断；前日书签只负责找回，不催促、不自动搬运。
54. 动画只表达明确的操作反馈和空间变化，加载之外没有常驻循环；成功反馈短暂、克制，并复用现有反馈轨道。
55. 画布工具层始终提供“对话”入口；Agent 面板覆盖画布但不是第三个一级视图或永久聊天档案，用户可随时收起并在当前会话中回来。
56. 普通捕获与面板输入拥有独立 draft；收起面板、翻页或切换总览不丢文字、token、对话历史或待确认状态，`⌘ J / Ctrl J`、Enter、Escape 和 Tab 行为稳定。
57. “这个”“它”只引用明确显示的当前 Card；多个同名目标通过一个最小问题消歧，用户选择前保持 Workspace no-op。
58. 唯一目标的可撤销操作直接执行并提供“查看 / 撤销”；批量操作先预览并原子提交；破坏性操作继续使用默认取消的安全确认层。
59. 模型只输出结构化意图，本地 policy 决定目标、确认等级和最终 action；模型不能直接修改 Workspace、生成坐标或绕过 Undo。
60. Agent 创建、移动、完成、定位和撤销复用现有 Card、Placement、视口、动画与焦点协议；对话结果真实出现在画布或总览，而不是只停留在文字中。
61. 外部模型只获得当前请求所需的最小上下文；首次启用前说明数据去向，启动与普通本地操作不发起网络请求，失败时 Workspace 保持原样，离线核心功能完整可用。
62. Agent 不主动问候、推荐、规划、复盘、催促或评价；回应短、准确且不续问，温度来自可靠和尊重沉默，不来自人格表演；对话会话只保留在当前应用内存中，重启后不恢复。
63. 画布与总览一次只挂载当前一级视图；Agent 面板按需挂载，收起后不保留可交互 DOM；总览首批最多 64 行，并可通过接近末尾自动续载或“再显示 N 张”手动入口到达全部 Card，完整数量和分组不因渲染批次失真。
64. 1,000 张代表性 Card 下，`pnpm test:performance` 验证捕获、翻页和拖放各 `<40ms`、搜索 `<30ms`、总览首屏 `<80ms`；性能通过不能替代 760×560、明暗主题、reduced-motion、悬停、焦点和真实拖动的窗口验收。
